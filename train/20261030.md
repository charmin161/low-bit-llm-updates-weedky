<a id="alto-mxfp4"></a>
## ALTO：把权重量化跳变纳入优化器｜ALTO-MXFP4｜论文实验｜10-23 首发、10-26 v2 UTC｜MI300X 数值模拟

**结论：**《Training an MoE LLM in MXFP4: How We Closed the Gap to BF16》给出 GPT-OSS-20B 的稳定性组合配方；最有价值的是消除权重振荡的端到端证据，而非四比特硬件速度宣称。

**技术机制与证据：** 激活沿 32 元素一维分组，权重采用 32×32 二维共享 scale，使转置前后的权重表示一致；后者是超出标准一维 MX 分组的训练设计。RHT 用于一维激活路径，梯度用随机舍入减轻小值归零偏差。AdamW 更新后，额外状态累计高精度权重与量化权重的移动距离；默认每 200 步检查一次，距离比超过 4 时把相应 master weight 拉回当前量化中心。这针对的是跨 bin 反复跳变，不能等同于简单裁剪离群点。

作者在 C4、序列长 8192、全局 batch 16、EP8 下训练；lm_head 与 router 不量化。16,128 步时验证 loss 为 3.3350，BF16 为 3.3283，不加去振荡为 3.3418。达到 3.34 目标所需步数相对 BF16 的额外开销由 20% 缩到 5%；验证每 768 步进行，步数结论具有该采样粒度。方法说明、设置和结果见[论文 v2 §3–5](https://arxiv.org/html/2610.32229v2)。

**边界与影响：** 论文实验在 MI300X 上先量化再反量化，用高精度 GEMM 模拟数值误差；不能写成原生 MXFP4 吞吐结果，optimizer state 也未因此成为四比特。论文报告的若干算子 SNR 改善未转化为更好收敛，提示局部重构误差不是配方排序的充分依据。可迁移的是转置一致性、梯度舍入及权重时间稳定性的联合考量；代价包括统计状态、额外变换和更新逻辑。下一步应跟踪原生 kernel、时间到目标 loss 及更长训练跨度，而非按理论 FLOPS 折算加速。[限制见 §6](https://arxiv.org/html/2610.32229v2#S6)。

这里应分开评价两个问题：给定相同步数，量化模型是否接近 BF16；给定同等质量，量化模型是否节约总时间。前者已有实验支持，后者还受每步量化、变换和优化器 hook 成本影响。对原生低比特平台的推广属于待验证推断，而非论文在另一平台测得的结论。

<a id="thinkbit-reasoning"></a>
## ThinkBit：用推理表现选择两比特恢复阶段｜THINKBIT-REASONING｜论文实验｜10-26 UTC｜Qwen3 / 作者推理实现

**结论：**《ThinkBit: Search Codewords, Recalibrate Scales, Select by Reasoning》表明，量化恢复后的困惑度改善与推理质量改善可以分离；因此按后训练质量贡献归入本栏。

**技术机制与证据：** 方法先按敏感度分配 ternary、2-bit、3-bit 层并搜索标量 codeword，再固定 codeword、用教师输出蒸馏学习 scale 和 norm，最后允许短程 QAT 改变 codeword。最终在训练问题上的成对推理评估中选择恢复阶段或 QAT 阶段 checkpoint，不直接按测试集选最优结果。scale 对齐的是全网输出分布，未必令每层权重或中间激活更接近 BF16。

关键消融是 Qwen3-1.7B、BF16 head/embedding：从重校准到基础数据 QAT，WikiText-2 perplexity 从 19.46 改善到 16.54，但 sampled MATH-500 从 47.5 降到 43.0。加入完整推理轨迹的数据方案改变了这一结果；应把数据和选择规则一并阅读，不能概括成“QAT 无益”。[方法、表4与推理数据消融](https://arxiv.org/html/2610.34886v1)。

**边界与影响：** 真正按位重打包的文件与 serving 容器必须分开：作者验证了紧凑文件可解码；论文 vLLM 路径则直接使用四比特容器，不能把文件标称两比特当成两比特 MMA。不同大小模型的有效 bits/parameter 还包含 scale、embedding 等开销。论文的速度观察只属于该运行路径，本期不把理论八倍压缩写成速度收益。训练时搜索、教师计算及恢复均有成本；下一项关键证据是更成熟的紧凑格式 kernel 与实际请求条件下的收益。[存储和部署边界见 §6、附录 M](https://arxiv.org/html/2610.34886v1#S6)。

这一结果对选型的启示是：应同时保留文件大小、实际权重驻留量和任务评分口径。恢复训练可能改善输出结束行为，也可能改变解题能力，两者共同决定最终分数。只看压缩率或 next-token loss，无法判断长推理是否会在预算内完成；不同模型规模的结论也不能互换。

<a id="te-group-row"></a>
## TE：动态 expert 路由可复用 row-scaled NVFP4 量化图｜TE-GROUP-ROW-NVFP4｜主分支提交｜10-27 UTC｜Blackwell / TE 89668d9

**结论：** row-scaled NVFP4 经统一 grouped quantize 接口获得设备端路由与 graph-safe amax/cast 路径；这是训练量化供给端的能力扩展，没有报告完整 step 加速。

**技术机制与证据：** MoE producer 把 token 排成 expert 分组，设备端 `first_dims` 和 `tensor_offsets` 描述有效区域；量化先计算每行 amax，再生成 packed E2M1、block scale 以及相应表示。与把 expert 大小固定在主机调用参数中的路径相比，capture 后更新设备路由即可 replay。最终代码走 `nvte_group_quantize`，不能照提交早期讨论宣传已经删掉的独立 helper，也不能把 amax 与 cast 两阶段说成单 kernel。

新增回归把路由从 `[256,128,128]` 改成 `[128,256,128]`，同一个 CUDA Graph 重放后逐位比较 payload、scale 与 amax。另测容量大于有效 token 数的缓冲、uniform shape 和非连续输入。它保护的不只是浮点重构误差，还包括“当前 expert 消费当前 scale”的契约；固定 shape 下数值相同不足以验证动态图。[最终实现及回归](https://github.com/NVIDIA/TransformerEngine/commit/89668d9dee82aba9b9107b37ed85227542a578d2)。

**边界与影响：** 当前 grouped 路径拒绝 RHT、二维量化、随机舍入、amax reduction 和 4over6；uniform expert 行数需 128 对齐，strided `first_dims` 有显式拒绝测试。这些条件意味着它不能直接替代任意 NVFP4 训练 recipe。row scale 增加元数据，后续 GEMM 仍须理解对应表示；本提交不改变 optimizer dtype，也不证明完整 Fprop/Dgrad/Wgrad 已默认命中该路径。预期收益来自减少逐 expert 调度和重捕获，不是改变 FP4 算术精度；是否抵消对齐、padding 与布局成本仍缺完整训练测量。

从源码可推断，graph-safe 的关键是让有效长度成为设备端动态数据，同时固定分配容量与可捕获的调用结构。它没有取消有效区与容量区的区别。下一步适配需要把路由、量化输出和 GEMM consumer 的约束一起传递，不能仅给量化 API 加上 CUDA Graph 包装便宣布完整 MoE 已支持动态重放。

## MXFP8 master-weight cast 可只生成 rowwise｜TE-MXFP8-ROW-MASTER｜主分支提交｜10-27 UTC

TE 根据输出 storage 是否存在选择 columnwise 计算，row-only primary 不再必做该方向的 amax、scale 更新与写出；请求 columnwise 时必须提供对应 scales。测试覆盖跨 32 元素 block 的 shard 边界、空 rank 和混合单双向权重。它减少无用表示和通信统计，未证明所有 backward 都能省掉转置权重，也不改 master weight 精度；尚无 step 吞吐结论。[固定 diff 与测试](https://github.com/NVIDIA/TransformerEngine/commit/38509867458c686b3ebc3af9a713c9fec7b1ad7b)。

<a id="modelopt-tp-kl"></a>
## 正确的 KL 数值可能掩盖错误的 TP 梯度｜MODELOPT-TP-KL｜主分支提交｜10-26 UTC

ModelOpt 修复 Top-K/Top-P 蒸馏中每个 TP rank 重复计算全局 loss、autograd collective 又累加梯度的倍乘。新式 `detach(loss)+(loss-detach(loss))/TP` 只缩放 backward。作者报告 A800 上 TP1/2/4 各 13 项定向测试通过，并以旧实现使梯度 reference 失败作负对照。该风险直接影响 QAD 更新幅度，不能靠 loss 日志排除；dense KL 不受此项改变，长期收敛未评估，短微基准不作为加速依据。[实现与验证说明](https://github.com/NVIDIA/Model-Optimizer/commit/8fef2144a3c4a163c8cd8c886b78e914519f7296)。
