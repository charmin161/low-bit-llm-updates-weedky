## 论文推荐

<a id="alto-mxfp4"></a>
### ALTO：稳定四比特训练，不能只优化单次量化误差

**论文更新 · 10-26。** AMD 团队在 GPT-OSS-20B 上结合分组量化、随机旋转、梯度随机舍入与“权重去振荡”，减少权重反复跨越量化档位的问题。达到同一验证损失目标时，相对 BF16 多出的训练步数由 20% 降到 5%。值得关注其负结果：一些改善算子误差的方法，反而没改善最终收敛。实验用 MI300X 模拟 MXFP4 数值，尚不能据此判断原生四比特训练的总耗时。

原文：[Training an MoE LLM in MXFP4，v2](https://arxiv.org/html/2610.32229v2)

<a id="thinkbit-reasoning"></a>
### ThinkBit：两比特压缩之后，要按推理能力选择模型

**论文发布 · 10-26。** 方法先分配不同层的位宽并搜索量化值，再通过蒸馏校准缩放参数，最后尝试短程量化感知训练。它用推理题表现选择最终模型，避免只追求困惑度下降。Qwen3-14B 的示例压到 3.74 GB，MATH-500 为 94.8，BF16 为 97.5；其他任务仍有损失。紧凑文件与实际运行格式要分开看：论文的 vLLM 路径使用四比特容器，不能称为原生两比特计算。

原文：[ThinkBit，v1](https://arxiv.org/html/2610.34886v1)

## Transformer Engine

<a id="te-group-row"></a>
### NVFP4 分组量化：适应 MoE 每步变化的专家负载

**已合入 · 10-27。** 新路径允许 GPU 上的路由信息驱动逐行缩放的 NVFP4 分组量化，同一个 CUDA Graph 可以在专家 token 数变化后重放。它改善的是“路由之后如何高效准备低比特数据”，有助于减少逐专家调用和重建执行图的开销。当前仍有对齐和量化配方限制，尚无完整训练步的加速数据。

原文：[分组量化实现与回归测试](https://github.com/NVIDIA/TransformerEngine/commit/89668d9dee82aba9b9107b37ed85227542a578d2)

<a id="te-row-master"></a>
### MXFP8 权重转换：按实际需要生成行向或列向表示

**已合入 · 10-27。** 分布式主权重转换现在可以只生成行向 MXFP8 数据，省去没有消费者的列向统计和写出。意义在于减少量化准备阶段的冗余工作，而不是继续降低位宽。需要反向或转置表示的算子仍须保留相应数据；主权重精度也没有因此降低，完整训练收益尚待评估。

原文：[row-only MXFP8 master-weight cast](https://github.com/NVIDIA/TransformerEngine/commit/38509867458c686b3ebc3af9a713c9fec7b1ad7b)

## NVIDIA Model Optimizer

<a id="modelopt-qat-cache"></a>
### QAT/QAD 权重缓存：同一步内不必反复模拟量化

**已合入 · 10-28。** 在一次优化器更新前，权重并未变化，但微批次前向与激活重计算会重复做模拟量化。新增缓存复用这份结果，用额外显存换取更少的重复计算。它适用于量化感知训练和蒸馏，需显式启用并满足量化器条件；缓存的是高精度表示的量化结果，不能当作原生 FP4 训练或显存压缩功能。

原文：[QAT/QAD fake-quantized weight cache，PR #3034](https://github.com/NVIDIA/Model-Optimizer/pull/3034)

<a id="modelopt-sharded-nvfp4"></a>
### 分布式 NVFP4 导出：补齐分片权重的打包环节

**已合入 · 10-29。** ModelOpt 增加 NVFP4 分布式张量分片的正确打包，并在 FSDP2 允许更新权重的阶段处理数据，避免重新分片时把量化结果换回浮点权重。这是大模型分布式量化导出的基础能力，可减少必须汇总整个模型的压力；完整“不汇总导出”仍属于后续组合功能，INT4、NF4、MXFP4 也不能直接套用同样的分片支持。

原文：[NVFP4 DTensor 与 FSDP2 打包，PR #3099](https://github.com/NVIDIA/Model-Optimizer/pull/3099)

## LLM Compressor

<a id="compressor-auto-subgraphs"></a>
### 自动按显存分组校准：减少手工选择一次处理几层

**已合入 · 10-29。** 新增自动子图分组，根据可用显存、权重与校准临时数据，决定一次处理多少连续层。GPTQ、AWQ、SmoothQuant 等方法可减少逐层搬运或分组过大的问题，适合关注大模型量化工具的易用性与资源效率。它是内存规划估算，并非绝不溢出的保证；无法估算的算法、流式数据等情况会退回保守路径。

原文：[自动 sequential targets，PR #3271](https://github.com/vllm-project/llm-compressor/pull/3271)

## AMD：Quark、TorchSpec 与 ROCm 训练生态

<a id="quark-eagle3"></a>
### Quark 把草稿模型训练与 MXFP4 目标模型接成完整流程

**官方技术博客 · 10-27。** Quark 0.13 提供实验性 EAGLE3 工作流，连接 vLLM 隐藏状态提取、TorchSpec/FSDP2 训练和推理导出。MI350X 示例以 MXFP4 MiniMax-M3 为目标模型，让草稿模型学习实际部署模型的输出。作者在指定 SPEED-Bench 配置下报告输出吞吐提高 47%，但首 token 延迟增加 18.5%。这里的新价值是训练到部署的适配完整性；草稿训练本身并未被证明全部使用低比特计算。

原文：[AMD Quark EAGLE3 训练博客](https://rocm.blogs.amd.com/artificial-intelligence/eagle3-training/README.html)

<a id="amd-mi308x-rl"></a>
### MI308X 强化学习案例：BF16 训练与 FP8 生成协同工作

**官方技术博客 · 10-28。** AMD 展示三节点 DeepSeek-V4 Flash 强化学习流程：Megatron-LM/AITER 负责 BF16 策略训练，vLLM 使用 FP8 权重和 KV cache 生成轨迹，更新后的权重在线传输并重新量化。75 步案例覆盖了生成、训练、评估与恢复。值得关注跨框架的量化一致性和权重更新链路；这是特定配置的完整运行案例，未提供可推广的低比特训练加速比例。

原文：[MI308X 与 AITER 强化学习栈](https://rocm.blogs.amd.com/ecosystems-and-partners/deepseek-v4-mi308-aiter-backed-rl/README.html)

## 本期可以带走的判断

- **精度评估要看最终任务。** ALTO 的算子误差与收敛结果、ThinkBit 的困惑度与推理表现，都说明局部指标不能替代最终质量。见 [ALTO](https://arxiv.org/html/2610.32229v2) 与 [ThinkBit](https://arxiv.org/html/2610.34886v1)。
- **训练效率也取决于量化准备成本。** 缓存、按需生成表示、分片打包，分别减少重复计算、冗余数据和不必要的权重汇总；这些系统工作值得和新数值格式一起跟踪。见 [ModelOpt 缓存](https://github.com/NVIDIA/Model-Optimizer/pull/3034)、[TE 按需转换](https://github.com/NVIDIA/TransformerEngine/commit/38509867458c686b3ebc3af9a713c9fec7b1ad7b)与 [NVFP4 分片打包](https://github.com/NVIDIA/Model-Optimizer/pull/3099)。
