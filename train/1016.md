## 低比特训练技术简报｜10 月 9—16 日

本周有两项扎实的新训练结果：FP4 rollout 对齐和 4-bit tensor-parallel 通信。工程侧则出现数个可能造成静默清零、错误 scale/data view 或错误梯度通信精度的修复。没有新的 4over6 kernel 或预训练 recipe；TRACE 仅把 4over6 作为 post-hoc baseline。

### 1. TRACE：让训练端 FP4 rounding 直接跟随 rollout codeword

TRACE 不再分别最小化 trainer/rollout 的量化误差，而是在 QAT forward 中：

1. 用 rollout 保存的 scale 归一化训练 activation；
2. 找到相邻两个 E2M1 codeword；
3. 选择更接近 rollout codeword 的那个；
4. 通过 STE 反传。

完整 rollout code/scale 数据可能达到每 RL step 数十 TB。默认配置只保存模型后半 20 层的 1-bit mantissa 与 scale，约 `7.5 KB/token`，较完整 activation guidance 缩小约 6 倍。

**已展示：**Qwen3.5-35B-A3B 在 NVFP4 W4A4 + NVFP4 KV rollout 下，四项平均分为 TRACE `75.3`、BF16 rollout `74.9`、普通 QAT `59.6`、QUADS `68.8`；结论还覆盖 122B、125B 和 2.4T MoE。端到端 RL step 相对普通 FP4 rollout增加 `7.4%`，128K 输出时 rollout 相对 BF16 最高 `5.4×`。[arxiv.org](https://arxiv.org/abs/2610.07767?utm_source=chatgpt.com)

**限制：**backward 仍为 BF16，未展示低比特 Dgrad/Wgrad；只量化 routed experts 与 attention KV，其余模块为 BF16。系统还要求 trajectory/token/site 精确对齐的额外缓存流水线，暂无代码发布。[论文](https://arxiv.org/abs/2610.07767)

### 2. Echo：前向 activation 与反向 gradient 的 TP all-reduce 都压到 4 bit

Echo 把 tensor-parallel all-reduce 改为：

```text
INT4 all-to-all
→ owner 高精度求和
→ INT4 all-gather
```

每个值与 GPU 数量无关，最多量化两次。它使用 group-size 128 的 zero-aware asymmetric quantizer，并分别对 forward activation 和 backward gradient 维护双时间尺度误差补偿状态。

**已展示：**

- Qwen3-0.6B、TP=4、10B tokens、12,716 steps：尾部 loss `3.225`，16-bit 为 `3.197`。
- 8×A100、1 GB message：collective 相对 NCCL BF16 快 `2.09×`。
- 无额外链路负载时，训练 step 快 `1.08–1.09×`；满负载时快 `1.34–1.38×`。[arxiv.org](https://arxiv.org/abs/2610.14277?utm_source=chatgpt.com)

**限制：**这是自定义 INT4 transport，不是 FP4 Tensor Core 数据格式；10B-token 实验只到 0.6B，而且 4-bit run 使用了更高峰值学习率 `3.5e-4`，BF16 为 `3.0e-4`，不是完全同参对照。尚无公开实现。[论文](https://arxiv.org/abs/2610.14277)

### 3. ModelOpt 修复 static NVFP4/LSQ 的“小值整张量清零”

FP8 fake-quant 原来把所有 `amax ≤ 2^-24` 当成零。Static NVFP4 用：

```text
FP8-scale amax = global_amax / 6
```

所以当 `global_amax < 6×2^-24 ≈ 3.6e-7` 时，每个 E4M3 block scale 都变成零，整个 tensor 会静默清零。LSQ block scale 和普通 tiny-amax FP8 也受影响。

修复把阈值改为 `448 / FLT_MAX`，即只有 `448/amax` 本身会溢出的极端值才按零处理。`2^-22` 常数 block 现在可正确保留；旧阈值外的输出逐位不变。

关键位置：

- `modelopt/torch/kernels/quantization/gemm/tensor_quant_gpu_fp8.cu`
- `modelopt/torch/quantization/tensor_quant.py`
- `tests/gpu/torch/quantization/test_lsq_cuda.py`

**限制：**这是 fake-quant/QAD 路径，不代表原生 NVFP4 GEMM 曾清零；只在 B300 完成验证，未覆盖 B200、FSDP 或多 GPU。[官方修复](https://github.com/NVIDIA/Model-Optimizer/commit/624c87c95a4cb418cb6a5864ac7c6f022a517736)

### 4. TE 修复两类 quantization 数据流错误

**TMA shared-memory 重用同步。** FP8、FP8 block scaling、MXFP8、NVFP4、RHT fusion 和二维 block-scaling 共 21 个文件统一改为：由发起 TMA 的 master thread 等待 async group，再通过 CTA-wide barrier 发布完成状态；PTX helper 同时加入 `"memory"` clobber。

**事实：**旧代码错误地假定其他线程也能等待 thread-local bulk async group。  
**推断：**特定 pipeline 时序下可能在 TMA 读完之前重写 shared output，造成 data/scale 损坏；提交没有给出复现频率、受影响 shape 或 loss 数据。[TMA 修复](https://github.com/NVIDIA/TransformerEngine/commit/39c30c577f5dd4f9fba921ee011b5cd797ae667e)

**Single-group fused MoE 的 NVFP4 weight view。**

- FC1 Fprop scale view 把逻辑 `K` 错按 packed-byte divisor 再除一次，索取了两倍 scale。
- FC2 Dgrad 把物理转置的 columnwise FP4 data 当成未转置 shape，并交换了 scale atom 轴。

现在 FC2 Dgrad 使用 `_convert_to_cudnn_grouped_gemm_tensor_format()`，单组测试扩展到所有量化 recipe。[NVFP4 view 修复](https://github.com/NVIDIA/TransformerEngine/commit/2e959f352c8e2d4b2709e6775867f2c7494656f3)

**限制：**已知症状主要是异常或 cuDNN 拒绝，不是已经证明的静默错误梯度；没有性能与收敛数据。

### 5. MLA 的 RoPE、KV split 与 MXFP8 quantize 合并为一个 kernel

DeepSeek-V3 风格 MLA 原路径为：

```text
KV up-projection
→ BF16 K/V split + K RoPE
→ 写回 BF16
→ 重读并量化 MXFP8 K/V
```

新 `fused_mla_kv_rope_mxfp8` 一次读取 `kv` 与 `k_rope`，直接生成 rowwise、columnwise MXFP8 K/V 和 compact scale；输出 bytes 与分离的 `mxfp8_quantize_only` 一致。

在 VR200、`[4096, 1, 128 heads]` 上为 `100.1 µs`，旧两段为 `60.8 + 75.6 = 136.4 µs`，减少约 `26.6%`。Megatron 已通过 `use_fused_mla_kv_rope_quant` 接入。

约束：

- SM100+、TP=1；
- `K=128+64`、`V=128`；
- MXFP8 attention backward 必须启用；
- 不支持二维 MXFP8 quantizer；
- backward 的 `dK/dV` 仍为 BF16，并复用原 RoPE backward。

[TE kernel](https://github.com/NVIDIA/TransformerEngine/commit/459dedc945a36abbb728479c165acc8a2c196968) · [Megatron 集成](https://github.com/NVIDIA/Megatron-LM/commit/fb65908da91d6185590ace81e2aeb84760c0566b)

### 6. MFSDP v2 终于按 `grad_comm_dtype` 分配 Wgrad reduce-scatter 输入

旧实现按 compute gradient 的 dtype 创建 `partial_grad`。因此即使：

```python
main_grads_dtype=torch.float32
grad_comm_dtype=None
```

Wgrad 仍可能先装入 BF16 buffer，再 reduce-scatter 到 FP32 `main_grad`；跨 rank 求和前已经损失精度。

新规则为：

```text
partial_grad dtype =
    policy.grad_comm_dtype
    or main_grad.dtype
```

测试显式覆盖 MXFP8 `QuantizedDBuffer`：权重物理 storage 虽为 `uint8`，gradient communication 仍按 BF16/FP32 policy，而不跟随 weight storage。

官方测试观察到 BF16 reduction 的最大 loss 差随 DP 增长：4 ranks 约 `4.5e-4`、16 ranks `1e-3`、256 ranks/宽 hidden `1.6e-2`；FP32 reduction 在这些测试中与 baseline 逐位一致。

**限制：**只修复 Wgrad collective/accumulation dtype，不改变 Wgrad GEMM operand 或 accumulator；FP32 通信成本更高，且“逐位一致”是测试观察，不是普遍保证。[官方修复](https://github.com/NVIDIA/Megatron-LM/commit/0adca6528c9fb100cd4ccc425f410795de9beafa)

## Worth testing

- 为 static NVFP4 和 LSQ 注入 `global_amax=2^-30…2^-20`，逐层检查 block-scale bytes、非零率及导出前后 packed codes。
- 对 TE TMA 修复前后运行高并发 CUDA Graph replay，对 FP8BS/MXFP8/NVFP4 的 data、row/column scale 和 Wgrad 输入持续做 hash。
- 构造 single-expert fused NVFP4 MLP，分别验证 FC1 Fprop 与 FC2 Dgrad 的 data shape、scale atom axes 和 dense reference。
- 对 MLA fused 开关做 profiler A/B；除 kernel time 外，逐位比较 row/column K/V bytes、scale bytes，以及 BF16 `dKV/dRoPE`。
- 在 MFSDP v2 上记录 `compute_grad → partial_grad → main_grad` 三段 dtype，并随 DP 规模测 Wgrad cosine、loss drift 和通信时间。
- 若试验 Echo，必须同时做同学习率对照，并将 forward activation 与 backward gradient 的补偿状态分别 checkpoint/restore。
