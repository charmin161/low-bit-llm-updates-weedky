## 论文与方法推荐

<a id="rare-fact-fp4"></a>

### 重点推荐：FP4 的损失曲线可能掩盖稀有事实学习变慢

《What the Loss Curve Misses》用可控出现次数的合成人物传记及混合网页文本，研究四比特预训练学到知识的效率。作者发现，验证损失接近时，NVFP4 模拟训练仍需要更多事实曝光才能达到 BF16 的召回水平，并把部分差距联系到梯度更新的噪声。它提示低比特配方应同时检查知识获取；这是受控模拟实验，不能直接外推到大模型原生 FP4 训练的速度或全部能力。

[论文原文](https://arxiv.org/abs/2611.12832)

<a id="transformer-fsq"></a>

### Transformer-FSQ：训练离散瓶颈，改变缓存表示

用有限标量量化（FSQ）瓶颈替换普通键值投影，把每个 token 的缓存存成打包整数码，不再附带逐 token 量化元数据。转换预训练模型时只训练这些投影，配套 Triton 内核直接读取离散码。作者在 0.6B—8B 模型上研究高压缩率下的检索质量；这需要额外学习和结构改造，不能视作现有 checkpoint 即插即用的缓存开关。

[论文原文](https://arxiv.org/abs/2611.09598)

## 框架与工具升级

### PyTorch

<a id="pytorch-quantize-api"></a>

#### 重点推荐：MXFP8 单向与双向量化进入公开接口

新增 F.quantize_tensor 与 F.quantize_tensor_dual，分别产生单方向或两个转置方向的量化数据和缩放，供训练前反向使用。首批接通 MXFP8 的 CuTe DSL 内核，避免不同训练栈各自维护相同的布局接口。目前仅支持所列 MXFP8 舍入配方，要求 NVIDIA 计算能力 10.0 及以上和可选依赖；NVFP4、MXFP4 与随机舍入仍列为后续工作。

[固定提交](https://github.com/pytorch/pytorch/commit/8d746590637f1c440c3cd0169e92923ea9b3e148)

### Transformer Engine

<a id="te-rowscale-gemm"></a>

#### 按行缩放 NVFP4 从量化扩展到分组矩阵乘

此前的分组量化本周接上实际分组 GEMM（矩阵乘），覆盖前向与权重梯度，并补齐缩放因子的交错布局。实现先把分组矩阵乘结果写入 FP32 临时空间，再应用外层行列缩放；因此要把中间存储成本与四比特乘法分开看。主分支附有图重放和数值对齐测试，相关测试门槛为 Blackwell 及 cuBLAS 13.4 以上，尚无统一端到端收益。

[固定提交](https://github.com/NVIDIA/TransformerEngine/commit/c4031d048bd84fdd57223428456c248704a9b015)

<a id="te-ue5m3-cublas"></a>

#### UE5M3 缩放的 NVFP4 接入 cuBLAS

常规和分组矩阵乘增加 UE5M3 缩放类型，替换原先借助 cuDNN 包装器的临时路径。UE5M3 是无符号、五位指数和三位尾数的八比特缩放表示；支持变化发生在缩放与库接口层，不能与其他 NVFP4 变体直接混同。实现明确要求编译和运行时 cuBLAS 均达到 13.11，尚未给出完整训练步测量。

[固定提交](https://github.com/NVIDIA/TransformerEngine/commit/42ec40e9512d0f39b13145c1d2d53976db6d504a)
