## 论文与方法推荐

<a id="flamia"></a>

#### FLAMIA：兼顾因果安全与前反向一致性的低比特注意力

重点推荐。FLAMIA 提供 Blackwell 上的 MXFP8 与混合 NVFP4/FP8 训练注意力，处理共享缩放因子泄漏未来信息、前反向数值不一致和文档打包问题。MXFP8 是以小块共享缩放因子的八比特浮点格式。作者在 B200/B300 的因果文档打包测试中，将量化、前向和反向一起计时；收益属于注意力调用，不能当作整步训练加速。全四比特路径并非默认，论文测试中也没有更快。

[论文原文](https://arxiv.org/html/2611.03344v1)

<a id="fp4quant"></a>

#### FP4Quant：把模型并行通信压到四比特

通过微分组双尺度量化、线程束协作打包，以及快速 Walsh–Hadamard 变换分散异常值，降低通信字节数并控制压缩开销。值得关注的是，方案把量化误差和 GPU 打包成本一起考虑。论文在 H100、Qwen-7B 上报告吞吐与质量之间的取舍；这里的 FP4 是通信压缩格式，不能据此推断 H100 原生执行 FP4 矩阵乘，也不能理解为无损训练。

[论文原文](https://arxiv.org/abs/2611.04323v1)

## 框架与工具升级

### Megatron-LM

<a id="megatron-parity"></a>

#### 重点推荐：MXFP8／NVFP4 MoE 的训练前向对齐生成路径

主分支加入可选的训练前向路径，复用生成端 FlashInfer 专家内核、路由顺序与合并算术，覆盖 MXFP8 和逐 token NVFP4。MoE 是每个 token 只调用部分专家的混合专家模型；这里针对训练与生成数值不同造成的强化学习概率偏差。反向仍由重计算的原训练路径提供，因此不是所有梯度都改成推理内核。实现附一致性测试，尚不能据此宣称长期强化学习收益。

[固定提交与源码](https://github.com/NVIDIA/Megatron-LM/commit/ebcf9d67221d3fc19bd131ff3e6077d6da6fea0a)

### Transformer Engine

<a id="te-batched"></a>

#### BatchedLinear：补齐 BF16／MXFP8 批量矩阵乘

新增带步幅的批量 GEMM（矩阵乘）和 PyTorch BatchedLinear，将一组线性计算接入 BF16／MXFP8 路径，并依据张量的批次维推断布局。实现包含布局、量化配方与梯度相关测试，扩展了训练算子覆盖。其他量化格式会回退高精度计算；MXFP8 仍有行数对齐约束。当前依据主分支合入，尚未给出端到端训练测量。

[固定提交与源码](https://github.com/NVIDIA/TransformerEngine/commit/b021980343e33fdd5b091f95fd13f82e05d581af)
