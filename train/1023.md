## 低比特训练技术简报｜10 月 16—23 日

本周没有新的 4over6 或 MXFP4 训练收敛结果。最值得关注的是 PACT 的 NVFP4 LoRA 数据流，以及 Transformer Engine 对分布式 NVFP4、grouped FP8 block scaling 和编译路径的补齐。

### 1. PACT：NVFP4 加速 LoRA 的 Fprop/Dgrad，并压缩反向状态

**已展示：**

- 七个冻结 projection 的 Fprop 使用 NVFP4×NVFP4，FP32 累加、BF16 输出。
- Dgrad 将 `dY` 量化为 NVFP4，并使用单独缓存的 backward-weight layout。
- forward weight 沿 `d_in` 每 16 个元素分组；backward weight 则先重构、转置，再沿 `d_out` 重新量化。两者的有效权重不完全一致。
- 冻结 base weight 没有 Wgrad；LoRA A/B 的 Wgrad 和 adapter 数据流仍是 BF16。
- RMSNorm 复用量化输出作为反向状态；SiLU gate/up 在 Fprop 用 BF16，但额外保存 NVFP4 副本供 backward。

权重 tensor scale 为：

\[
s_W=\frac{\max|W|}{448\times6}
\]

每个 16-value block 搜索九个 multiplier：`1.5, 1.25, 1.0, 0.95, …, 0.70`；候选 block scale 先舍入到 UE4M3，再测 E2M1 重构误差。GPTQ Hessian 由重构后的 NVFP4 activation 计算，而不是原始 BF16 activation。

RTX 5080 16GB、1–3B 模型上，相对 BF16 LoRA，峰值显存下降 `47–51%`，同 shape step speedup 为 `1.7–1.9×`；九项分类任务平均精度差最多 2.6 个百分点。[arxiv.org](https://arxiv.org/html/2610.25048v1?utm_source=chatgpt.com)

**限制：**仅单 GPU、小模型；attention 仍为 BF16；没有 base-weight Wgrad，因此不能视作完整 NVFP4 训练。论文也未给出公开实现仓库。[论文](https://arxiv.org/abs/2610.25048)

### 2. TE 首次让 NVFP4 进入 cuBLASMp 通信–GEMM overlap

cuBLASMp `≥0.11.0` 新增 device-pointer alpha/beta 后，TE 可以直接在 GPU 上从两个 operand 的 global `amax` 计算 NVFP4 GEMM alpha，无需 host sync。

反向数据流为：

```text
dY BF16
  ├─ rowwise NVFP4 → AllGather + Dgrad GEMM
  └─ columnwise NVFP4 → AllGather → Wgrad GEMM
```

`dY` 只量化一次，因此两个方向共享同一次 stochastic-rounding realization；不会为了 Wgrad 再量化并抽取另一组随机数。GEMM 使用 TN layout、VEC16 UE4M3 scale。

同周的另一个提交让 BF16 和 per-tensor FP8 Wgrad 直接复用 Dgrad all-gather 后留在 cuBLASMp workspace 中的 tensor。4×H100 测试中，row-parallel Linear 每次 backward 的额外 all-gather 从 `1→0`，LayerNormMLP 从 `2→1`。MXFP8、NVFP4、delayed Wgrad 或跳过 Dgrad 时仍需独立 gather。

**限制：**不支持 row-scaled NVFP4、UE5M3 scale、量化输出或 Userbuffers；`N/TP` 非 128 倍数时部分 RS/AR 路径回退默认算法。没有吞吐或 overlap 比例数据。[NVFP4 cuBLASMp 提交](https://github.com/NVIDIA/TransformerEngine/commit/6b5cd7e2e43cee6da5dff9b9f86bc2ec05d7b1ad)、[Wgrad gather 复用](https://github.com/NVIDIA/TransformerEngine/commit/1aaede2f9edcaf70020c112c673e0b16818bc6a4)

### 3. Blackwell grouped FP8 block scaling 改由 MXFP8 GEMM 执行

Blackwell cuBLASLt 没有原生 grouped FP8 block-scaling GEMM。TE 现在：

1. 保留 FP8 E4M3 data；
2. 将每个 128-value FP8BS scale 广播成四个 MXFP8 `1×32` E8M0 scale；
3. swizzle 到 grouped-GEMM layout；
4. 以 MXFP8 TN GEMM 执行。

新的 persistent scale-conversion kernel从设备端读取各 expert shape，因此 CUDA Graph replay 可改变 split size，包含 zero-token experts。离散 per-expert weights 最多 128 个 tensor 可在一次 multi-tensor launch 中转换。

**实现约束：**

- Blackwell 只接受 power-of-two FP8BS scale；非 PoT recipe 会直接拒绝。
- 每个 expert split 必须为 128 的倍数。
- 若环境中设置过 `NVTE_FP8_BLOCK_SCALING_FP32_SCALES`，需在 import TE 前取消。

**判断：**这打通了功能，但额外 scale-broadcast/swizzle 是否抵消 grouped-GEMM 收益仍未知；提交没有 kernel 或端到端性能数据。[官方提交](https://github.com/NVIDIA/TransformerEngine/commit/f4a69dc81eabb5002a662e56a36e8454c9840a92)

### 4. Qwen3.6 QAD：assistant-only chat SFT 的早期优势不能保持

Model Optimizer 新增三种数据格式的完整消融：

- pre-tokenized 32K blend，全 token KD；
- chat SFT，仅 assistant token KD；
- BF16 teacher 重新生成 response 的 self-distilled chat SFT。

结果：

- 50 step：chat SFT 平均差距 `−0.34`，优于 pre-tokenized 的 `−1.30`。
- 500 step：chat SFT 退化到 `−0.83`，pre-tokenized 为 `−0.30`。
- chat SFT 消耗约 `2,150 GPU-hours`，是 pre-tokenized `735 GPU-hours` 的约 `2.9×`。
- SciCode capped rate 为 `5.7%`，高于 pre-tokenized 的 `3.6%`。

新的 full-vocabulary probe 还显示：teacher top-4096 已覆盖几乎全部概率；student 会在 teacher 停止的位置停止，但一旦进入循环，teacher 本身也倾向继续循环。因此，仅改变 top-k 覆盖、assistant mask 或 teacher-generated response 并未消除 free-running loop entry。

工程上现已提供：

```bash
--sft_in_batch_packing
--moe_aux_loss_coeff 0
```

但 packed THD 路径的 Gated DeltaNet teacher logits 存在 `0.001–0.007 nat/token` 的非确定性，而 KD loss 约为 `0.03`，所以 chat-SFT 与 pre-tokenized 的差距仍带有系统噪声。

**限制：**这是 fake-quant QAD，高精度 backward；不能证明 NVFP4 Dgrad/Wgrad。[数据格式与终止行为消融](https://github.com/NVIDIA/Model-Optimizer/commit/d074dd3e410c2df72a5b13b4331eec459635d2bc)、[SFT packing 实现](https://github.com/NVIDIA/Model-Optimizer/commit/f1d68fd4dd50c6aeb357defcb75bedd8f7184b54)

### 5. TE 修复 compiled NVFP4 Linear 的 columnwise metadata

`torch.compile` fake execution 与 native NVFP4 quantization 对 columnwise buffer 的描述曾不一致。修复包括：

- 3D/4D activation 按 native kernel 实际使用的 flattened 2D shape 描述；
- 跨 custom-op 保留 compact/swizzled scale layout；
- bias backward 输出使用 fused-quantization 的实际 layout；
- 修正 row-scaled NVFP4 columnwise `amax` metadata；
- Dynamo 与 native 路径共用 alignment 判定。

另一个一行修复把调用者提供的 RHT matrix 传入 quantize dispatch，恢复 SM120/121 的 columnwise RHT；旧代码会因 matrix 为空触发检查失败。

**限制：**没有提交前后梯度误差或性能数字；RHT 修复主要影响 SM120/121，不影响 B200 的 SM100 路径。[compiled metadata 修复](https://github.com/NVIDIA/TransformerEngine/commit/f0b1096128c0f41e18c6d0b4d6b4a3d749c0f008)、[RHT dispatch 修复](https://github.com/NVIDIA/TransformerEngine/commit/4a3a8a8e8578e96319467d0cc96b9f5db552a7d3)

### 6. ModelOpt 修复 vLLM TP calibration 的跨 rank `amax`

在 TP>1 的 vLLM fake-quant calibration 中，每个 rank 此前只保留本地 shard 的 activation `amax`，但导出 checkpoint 通常只有一个 layer-level scale。

Qwen3-4B、TP2、NVFP4 实测：

- `down_proj.input_quantizer`：修复前 36 层中 `0` 层两 rank 相同；
- 最坏 `amax` 为 `3620` 对 `11.2`，相差 `323×`；
- 修复后 `36/36` 相同。

同步现在按 quantizer axis 处理：per-tensor scale 跨 TP 同步；per-channel 只在 row-parallel 情况同步；static block scale 不做错误的跨 shard MAX。同时移除会把不同 TP channel 混在一起的 EP group。

**限制：**这是 calibration/验证路径，不是低比特训练 kernel；TP-sharded FusedMoE experts、attention `q_bmm_quantizer` 和 PCP 尚未覆盖。旧 TP>1 calibration 应重新执行。[官方修复](https://github.com/NVIDIA/Model-Optimizer/commit/f6d0771184490056a82ea3b9ce339471900796fc)

## Worth testing

- 在 PACT-style Linear 中分别 hash forward/backward packed weight 和 scale，测两套有效权重的差异对 Dgrad bias/cosine 的影响。
- 对 cuBLASMp NVFP4 固定随机种子，确认 Dgrad/Wgrad 确实共享一次 `dY` 量化；记录 row/column packed bytes 与 all-gather 次数。
- 对 Blackwell FP8BS grouped 路径统计 scale-conversion kernel 时间，并扫描 expert split、zero-token expert 和 CUDA Graph replay。
- QAD 实验同时报告 free-running capped rate、teacher-forced KL、packed/unpacked teacher-logit variance，避免只比较平均准确率。
- 对 compiled NVFP4 Linear 覆盖 `[B,S,H]`、4D、singleton、compact/swizzled scale 和 row-scaled activation，逐项比较 eager/compile/CUDA Graph 的 Fprop、Dgrad、Wgrad。
- 在 TP1/2/4 下校准同一模型，比较导出 scale bytes 和 fake-quant logits；TP 大小不应再改变 per-tensor `amax`。
