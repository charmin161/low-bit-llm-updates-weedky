## 低比特训练技术简报｜8 月 21–28 日

本周没有新的 4over6 训练结果或 NVFP4 Fprop/Dgrad/Wgrad 精度 recipe。高信号进展主要是 MXFP4 蒸馏方法、MXFP8 分布式正确性，以及 Transformer Engine 的反向数据流融合。

### 1. QAH：结构压缩后的 4-bit 模型应向原始大模型蒸馏

新论文提出 Quantization-Aware Healing：对于 `120B → 60B → MXFP4` 这类先做结构压缩、再量化的流程，MXFP4 student 不再向压缩后的 BF16 checkpoint 学习，而是直接向原始 120B teacher 学习。

已展示结果：

* 60B MXFP4 student 在 9 项测试中有 7 项达到或超过自身 BF16 checkpoint。
* 20B→9B 实验中，QAH 约 100 step 达峰；普通 QAT 约 700 step，且之后继续训练会下降近 19 分。
* 实际配置：STE MXFP4 fake quant、`temperature=1`、离线保存 teacher top-100 logits、32K 序列、global batch 64、学习率 `5e-6`、400 step；冻结 embedding、LayerNorm 和部分 attention。
* chunked KL 避免完整保存 `[B,L,V]`，作者称与 dense KL 逐位一致。

重要限制：没有最关键的“原始 teacher 与压缩 BF16 teacher”同配置直接对照；只有一个模型族、一种 MXFP4 格式和单次实验。反向仍是高精度 fake-quant 训练，不是 MXFP4 Wgrad/Dgrad。论文观察到 FSDP2 与 DeepSpeed 存在显著质量差距，但“与混合精度通信有关”只是作者推测，尚未定位数据流原因。[论文全文](https://arxiv.org/html/2608.20953)

### 2. Megatron 修复 GTP + Muon + MXFP8 参数同步的数值错误

Megatron-LM 8 月 27 日修正了两处可能让 rank 间实际使用不同权重的问题：

```text
FP32 master update
  → 显式写入 BF16 all-gather staging buffer
  → parameter all-gather
  → TE MXFP8 storage 更新
```

此前 TE 管理的 MXFP8 parameter storage 与 DDP parameter buffer 并非同一存储，更新 `param.data` 不一定更新 all-gather 输入；现在 owner rank 会从 `main_param` 显式填充对应 buffer slot。

另外，FP32 master 初始化不再从已经量化过的 parameter clone，而是优先读取 `get_high_precision_init_val()`，避免 primary-weight 与普通权重从不同初值开始。代码集中在：

* `param_and_grad_buffer.py::_stage_layerwise_mxfp8_params`
* `optimizer.py` 的 FP32 master 创建
* `layer_wise_optimizer.py`

`--use-layer-wise-distributed-optimizer` 与 `--moe-single-grouped-weight` 现在直接禁止组合，因为 Muon 对 `[E,N,K]` grouped weight 的更新语义尚未定义。限制是提交只有单元测试，没有大模型 loss/grad-norm 或通信性能对比。[官方修复](https://github.com/NVIDIA/Megatron-LM/commit/af7e4f6160910146056d72c89370cf083b258e28)

### 3. TE 将 grouped MXFP8 的 Wgrad 重建链融合成一个 kernel

上期提到的 MoE 接收端：

```text
rowwise MXFP8
 → dequantize
 → per-expert columnwise quantize
 → row/column scale swizzle
 → columnwise MXFP8 供 Wgrad
```

现在被一个 `nvte_group_requantize` kernel 替代。它同时生成：

* 供 Fprop 使用的 GEMM-swizzled rowwise scale；
* 供 Wgrad 使用的 columnwise MXFP8 data/scale；
* 可选 BF16 dequantized output。

可设置：

```bash
NVTE_FUSED_GROUP_REQUANTIZE=0
```

恢复旧链路，便于 A/B。测试将 fused 与 unfused 的 data、scale、可选 BF16 输出逐位比较，并检查 capacity tail 没有越界写入。

限制：仅 Blackwell+；hidden size、各 expert live rows 和容量均按 128 对齐；没有 kernel 时间或端到端 step-time 数据。`use_fast_math` 对应 BF16 中间舍入，否则参考语义使用 FP32，因此融合前后不能只比较最终 loss。[官方提交](https://github.com/NVIDIA/TransformerEngine/commit/8d9325faed7f7b6baeeac3dba0fa4042f12bf5e5)

### 4. FP8 fused attention 补齐 THD/变长序列前向与反向

TE 现在允许 FP8 fused attention 处理 THD packed/ragged 输入，覆盖 Q/K/V/O、`dO/dQ/dK/dV` 和 softmax Stats 的 ragged offsets。

启用条件：

* cuDNN `≥9.23`
* SM100+
* padding mask
* 优先使用 int64 ragged offsets

这使 packed-sequence 训练不必为了 FP8 attention 退回 padded 高精度路径。当前范围只是 attention Fprop/backward，不涉及 Linear Wgrad、MXFP4 或 NVFP4。提交也没有吞吐和收敛数据；SM120 的 Stats 仍采用 dense layout，THD comparison 的 fast zero-fill 因段错误被关闭。[官方提交](https://github.com/NVIDIA/TransformerEngine/commit/ffcb3c0013dbdead74a144c5aef890f62be86d2a)

### 5. Model Optimizer 修复“QAD 训练了 MTP，但导出仍是旧 BF16 权重”

此前 `_get_mtp_state_dict` 没有遍历实时的 `model.mtp`，而是从预训练 safetensors 复制 MTP head。因此：

```text
MTP quantization / co-training
        ↓
导出时被静默丢弃
        ↓
部署的仍是原始 BF16 MTP
```

修复后，exporter 直接遍历 live MTP module，并复用 backbone 的 attention、MoE 和量化导出规则，生成 `mtp.layers.*` 下的 packed weight 与 scale。没有 MTP module 时才保留旧的 pretrained-head graft 行为。

验证覆盖 Nemotron-H hybrid MTP 的 HF key layout，但没有端到端 speculative acceptance、scale 数量或 QAD 质量结果。旧版本导出的“量化 MTP”checkpoint 应视为可疑，不能只检查导出是否成功。[官方修复](https://github.com/NVIDIA/Model-Optimizer/commit/d0ada2a10acd58e83b3c02807dc1ad2eb5c950d5)

### 6. “Great Inversion”给出了 rotation 与 microscaling 的统一解释

这是一篇覆盖约 200 项工作的理论综述，而不是新 kernel。其核心区分是：

* 可自由分配码率的经典 transform coding 倾向于集中能量；
* 硬件共享 scale、每元素固定 bit 数的 microscaling GEMM 倾向于让同一 scale group 内的幅值变平。

具体到格式：

* MXFP4 的 E8M0 scale 和 32 元素 group 仍明显受 scale rounding 影响，因此 rotation 通常应限制在 group 内或接近 group 大小。
* NVFP4 的 16 元素 E4M3 scale 能表达 mantissa，降低了 group-level scale penalty；某些实验中额外 Hadamard 接近无收益甚至略有损害。
* 对训练，现有大规模 NVFP4 recipe 是只对 Wgrad GEMM operands 做 16 元素 RHT，而不是统一旋转 Fprop、Dgrad 和 Wgrad。

这是很有用的设计原则，但跨论文结果来自不同模型、rounding 和校准设置，不能视为统一 benchmark。工程含义是：不要把“Hadamard 能压 outlier”直接推广为三个 GEMM 都应旋转。[论文全文](https://arxiv.org/html/2608.25188)

## Worth testing

* 对 QAH 做严格三组对照：原始大 teacher、压缩 BF16 teacher、hard-label QAT；固定数据、step、seed、冻结范围和 fake-quant 配置。
* 在 GTP + MXFP8 下，每个 optimizer step 后分别 hash `FP32 main_param → BF16 gather buffer → gathered weight → TE MXFP8 dequant weight`，确认所有 rank 一致。
* 使用 `NVTE_FUSED_GROUP_REQUANTIZE=0/1` 做 profiler A/B，同时比较 row/column data、scale、tail sentinel 和 Wgrad，而不仅是最终输出。
* 对 FP8 THD 与 padded reference 比较 attention Fprop、`dQ/dK/dV`，并确认 cuDNN 版本、mask 类型和实际 backend 没有回退。
* 在 MTP 权重中注入可识别扰动后完成 QAD export/import，断言扰动及对应量化 scale 存在于 `mtp.layers.*`，再测 speculative acceptance length。
