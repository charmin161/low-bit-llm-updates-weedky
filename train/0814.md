## 低比特训练技术简报

检索以 2026 年 8 月 7–14 日为主。本周没有值得单列的新低比特训练论文；高信号变化主要来自 Transformer Engine 的二维 MXFP8、MoE 通信数据流，以及 Model Optimizer 的 4over6/QAD 正确性修复。

### 1. TE 为 MXFP8 权重加入真正的 `32×32` 二维量化

8 月 13 日，Transformer Engine 新增：

```python
recipe = MXFP8BlockScaling(enable_2d_quantization=True)
```

启用后，TE 只对 Linear/GroupedLinear 的前向权重使用二维 MXFP8：

* 每个 `32×32` weight block 共同计算一个 `amax` 和 E8M0 scale。
* 同时生成 rowwise 和 columnwise FP8 数据，但二者共享该方形 block 的 scale。
* 因此权重转置不会重新分组，Fprop 与 Dgrad 使用的有效 weight 数值保持一致。
* input、`dY` 和 backward quantizer 仍使用普通一维 MXFP8；所以它没有解决 Wgrad 两个 operand 的转置一致性。

关键位置：

* `common/cast/mxfp8/quantize_mxfp8.cuh`
* `common/cast/mxfp8/group_quantize_mxfp8.cuh`
* `pytorch/quantization.py`
* `pytorch/tensor/mxfp8_tensor.py`

测试覆盖 BF16/FP32 输入、E4M3/E5M2 输出、普通与 grouped quantization，并要求 scale 与参考实现零差异。[官方提交](https://github.com/NVIDIA/TransformerEngine/commit/d8815c4)

这与前期“转置不变 FP4”论文的数值动机一致，但不要混淆：这里是 MXFP8 weight-only `32×32` kernel，不是论文所需的全训练二维 FP4。

局限：仅支持 Blackwell；没有收敛、吞吐或显存数据，也没有把二维 scaling 用到 gradient/Wgrad。

### 2. NVFP4 stochastic rounding 曾在 SM120/121 静默输出全零

8 月 12 日修复了一个严重的架构相关问题。NVFP4 的 E2M1 stochastic-rounding helper 原先只在 SM100/103 使用硬件 `cvt.rs`：

* SM120/121 会进入 `assert(0)` fallback。
* release build 定义 `NDEBUG` 后 assert 被移除，量化 kernel 会继续运行并返回全零 FP4 数据。
* 这不是小幅 rounding 差异，而是整个被量化 tensor 可能静默归零。

新 fallback 使用软件 stochastic rounding：

```text
每个元素消耗 8 个随机位
→ 按所在 E2M1 区间选择 0.5 / 1 / 2 的 grid step
→ jitter + floor
→ satfinite 到 ±6
```

作者穷举全部 `2^32` FP32 bit pattern 的抽样随机位，并验证与原实现逐位一致；branchless 版本在 SM121 microbenchmark 中快 `1.34×`。[官方提交](https://github.com/NVIDIA/TransformerEngine/commit/fc1fc0e)

对你的 B200（SM100）没有直接影响，它仍走原生 `cvt.rs`。但任何在 SM120/121 上运行 NVFP4 gradient stochastic rounding 的 TE 版本都应立即包含此修复。

局限：没有公开端到端模型受影响的范围；`1.34×` 只是孤立软件-rounder microbenchmark。

### 3. Nemotron-3.5-Lightning 公开完整的 W4A16 NVFP4 4over6 QAD recipe

8 月 11–13 日，Model Optimizer 加入 Nemotron-3.5-Lightning-30B-A3B 的正式量化与 QAD 流程。核心 recipe：

`modelopt_recipes/huggingface/models/nvidia/Nemotron-3.5-Lightning-30B-A3B-BF16/ptq/w4a16_nvfp4_4o6.yaml`

实际混合精度分配为：

* routed/shared expert 与 `lm_head`：W4A16 NVFP4 4over6；
* Mamba `in_proj/out_proj`：FP8 W8A8；
* KV cache：FP8；
* attention、activation 和 MTP：BF16。

4over6 的 scale 选择被明确写成：

```yaml
algorithm:
  method: mse
  fp8_scale_sweep: false
  start_multiplier: 1.0
  stop_multiplier: 1.5
  step_size: 0.5
```

即每个 16-value weight block 比较：

```text
amax × 1.0 → 映射到 E2M1 最大值 6
amax × 1.5 → 等效映射到最大值 4
```

然后保存 MSE 更低的候选 scale。选择结果已经烘焙进 `_amax`，部署时不增加额外 metadata 或 kernel。

Megatron-Bridge QAD 示例使用 8×4 GPU、CP4、EP16、200 iterations、32K 序列与约 419M tokens，并通过冻结 BF16 teacher 蒸馏 NVFP4 student。[4over6 recipe](https://github.com/NVIDIA/Model-Optimizer/commit/4ca7dd8)、[QAD launcher](https://github.com/NVIDIA/Model-Optimizer/commit/71b3d88)

局限：未公布 PTQ→QAD 的 loss、MMLU 或吞吐提升。这证明了官方生产配置和可复现流程，尚未证明 419M-token QAD 的收益。

### 4. TEGroupedMLP 改为每个 expert 独立选择 scale

8 月 7 日，Model Optimizer 将 TEGroupedMLP 从“整层共享一个 weight quantizer”改为：

```text
GroupedQuantizer
  ├─ expert 0 TensorQuantizer + 独立 amax
  ├─ expert 1 TensorQuantizer + 独立 amax
  └─ ...
```

这会直接影响 NVFP4、4over6 和其他静态 scale 方法：不同 expert 不再因为动态范围不同而共享同一组 calibration 状态。独立 quantizer 贯穿 PTQ calibration、QAD、checkpoint restore 和 HF/Megatron/vLLM export。

工程注意事项：

* 这是 ModelOpt 0.47 的 breaking change。
* 旧 TEGroupedMLP checkpoint 的单量化器 `_amax` layout 与新版本不兼容，需要重新 PTQ/QAD。
* 可在模块转换前设置：

```bash
MODELOPT_TEGROUPED_COMPILE_WEIGHT_LOOP=1
```

启用 per-expert weight loop 的 `torch.compile` 路径；默认仍是 eager。

* 如果本地 expert 数多于加载到的 quantizer 数，export 会警告并让多余 expert 复用最后一个 scale。这通常意味着 TP/EP layout 不匹配，不应忽略。

[官方提交](https://github.com/NVIDIA/Model-Optimizer/commit/2ded5ab)

局限：提交主要验证 shape、restore/export 和 compiled/eager parity，没有公布每专家 scale 对模型质量的实际改善。

### 5. MXFP8 MoE dispatch 现在保留低比特 Fprop，同时为 Wgrad重建转置表示

TE 连续两个提交补齐了 MoE expert-parallel 的 MXFP8 数据流：

```text
发送端：
BF16 token → rowwise MXFP8 → EP dispatch

接收端：
rowwise FP8 data 原样保留
scale → 转成 GEMM-swizzled layout
rowwise MXFP8 → dequantize → columnwise-only MXFP8
                                  └→ Wgrad
```

具体行为：

* 已经通过网络发送的 rowwise FP8 data 不再重新量化。
* 如果 expert weight 需要梯度，接收端从“rowwise MXFP8 的反量化结果”生成 columnwise MXFP8，供 Wgrad 使用。
* dequantized buffer 同时用于 bias-gradient reduction。
* dispatch-forward 与 combine-backward 使用独立 quantization recipe。
* 支持 zero-copy symmetric-memory、1F1B CUDA Graph capture 和持久 receive buffer。

这保证 Wgrad 基于实际发送的低比特 activation，而不是不可恢复的原始 BF16 activation，属于数值一致性设计。[rowwise grouped-GEMM 支持](https://github.com/NVIDIA/TransformerEngine/commit/da28058)、[MXFP8 EP dispatch/combine](https://github.com/NVIDIA/TransformerEngine/commit/56a05e7)

局限：columnwise Wgrad 表示仍需要一次 dequantize→requantize，并非真正的网络低比特 transpose；仅支持 Blackwell，且没有通信吞吐或训练 step-time 数据。

### 6. 修复 untied `lm_head` 在 QAD 后静默回退 BF16

Model Optimizer 还修复了 Megatron-Bridge 的高风险 checkpoint 问题：当 `tie_word_embeddings=false` 时，`output_layer` 的 NVFP4 scale buffer 可能没有注册，distributed checkpoint 会静默跳过这些 key，最终导出 BF16 `lm_head`，且不报错。

修复后：

* restore 前显式 materialize per-block `_amax` buffer；
* QAD 期间保持 `output_layer.weight_quantizer` 启用；
* 导出包含 packed `lm_head.weight`、`weight_scale` 和 `weight_scale_2`。

官方在 Nemotron-Nano-3、4×GB200 上验证得到 52 shards、18,487 keys，并能由原生 vLLM 0.26.0 TP2 加载。[官方提交与验证](https://github.com/NVIDIA/Model-Optimizer/commit/1b3fd43)

这是 demonstrated correctness fix，不是精度提升；使用旧代码生成的 untied-output checkpoint 应重新检查，而不能仅看导出成功。

## Worth testing

* 在 B200 上用 `MXFP8BlockScaling(enable_2d_quantization=True)` 对同一 weight 分别生成 row/column 表示，验证反量化后逐位一致；比较一维/二维 weight 的 Fprop、Dgrad MSE，确认 Wgrad 不受 recipe 开关影响。
* 对现有 TEGroupedMLP checkpoint 断言：`len(weight_quantizer) == num_local_experts`，并画出每个 expert 的 `_amax` 和 4/6 选择比例；不要接受“复用最后一个 expert scale”的 warning。
* QAD 导出后直接检查 `lm_head.weight.dtype`、`weight_scale`、`weight_scale_2`，并与 `tie_word_embeddings` 配置交叉验证。
* 对 MXFP8 EP 路径记录 dispatch buffer、rowwise data 和 Wgrad columnwise data 的指针与 hash；确认 rowwise data 没有二次量化，同时统计接收端 dequantize/requantize kernel 成本。
* 在你当前 B200 环境反汇编 NVFP4 SR kernel，确认命中原生 `cvt.rs`；若以后迁移至 SM120/121，再专门加入“量化结果非全零”的回归断言。
