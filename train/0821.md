## 低比特训练技术简报

检索范围以 2026 年 8 月 14–21 日为主。本周最强的新结果是 QUASAR 的 loss-aware NVFP4 scale selection；工程侧则集中在 grouped Wgrad、混合量化数据流和分布式精度修复。没有发现新的 4over6 训练论文，但 TE 新增了 4over6 CUDA Graph `noop` 回归覆盖。

### 1. QUASAR：用梯度二阶矩选择 NVFP4 scale

8 月 14 日发布的 QUASAR 把 loss-aware reconstruction 放进每次 QAT/QAD forward：

* 使用 AdamW 的二阶矩 EMA 作为逐权重 saliency：
  [
  \hat S=\sum_i h_i(r_i-w_i)^2
  ]
* 对多个 clipping factor 搜索 E2M1 code assignment。
* 固定 codes 后，以 saliency-weighted least squares 求最优 dequant scale。
* NVFP4 的 tensor-level FP32 scale 仍由全局 `amax` 决定；只优化每 16 个权重的 FP8/E4M3 scale。
* 搜索范围为 `0.30…1.00`，步长 `0.05`；仍使用普通 STE，不改变 activation quantization 或 backward。

Qwen3-8B 上，真实 NVFP4 checkpoint 的 held-out KL 从 `0.016` 降至 `0.011`，九项平均准确率从 `67.1` 升至 `67.6`；Qwen3.5-9B 为 `0.009→0.006`、`69.4→70.2`。INT3 的匹配测试中每步开销增加 `1.4%`。[论文与完整方法](https://arxiv.org/abs/2608.13966)

为什么重要：它把此前的 max/MSE/LSQ scale 选择统一成“按 optimizer saliency 最小化重构误差”的在线问题，而且导出格式不变。

局限：NVFP4 训练仍是 fake quantization，activation 与反向计算没有低比特化；没有 Blackwell 训练吞吐、Fprop/Dgrad/Wgrad kernel 数据，也尚未公开代码。因此证明的是 QAD 质量收益，不是 FP4 训练加速。

### 2. TE 补齐 GroupedLinear 的 per-token NVFP4 Wgrad

8 月 14 日，Transformer Engine 将 dense Linear 已有的 row-scaled activation backward 扩展到 MoE `GroupedLinear`。设置：

```python
NVFP4BlockScaling(
    row_scaled_activation=True,
    backward_override=None,
    disable_rht=True,
    disable_stochastic_rounding=True,
    disable_2d_quantization=True,
)
```

后，Wgrad 不再退回高精度。Wgrad 的 row-scaled activation 作为 `NT` GEMM 的 A operand，columnwise storage/amax 按每列分配。

当前实现不是一个真正的 grouped FP4 kernel：检测到任一 row-scaled operand 后，会逐 expert 调用 dense `general_gemm()`。测试验证 1/3 experts、BF16、带/不带 bias 时，Fprop、Dgrad、Wgrad 与独立 dense Linear 逐位一致。[官方提交](https://github.com/NVIDIA/TransformerEngine/commit/621da35fff6491d302c47c574571e1ce15ce56b8)

局限：测试关闭 RHT、SR、二维量化和 fused Wgrad accumulation；`D_dtype` override 不支持，也没有性能数据。事实是“数值路径已打通”，不能推断它保留 grouped-GEMM 吞吐优势。

### 3. TE 重构 grouped 混合量化 dispatch

8 月 19 日新增 `_split_quantization.py`，使 `GroupedLinear` 可以可靠处理 `HybridQuantizer` 的两个方向：

* rowwise 与 columnwise 可以使用不同格式，例如 NVFP4 与 MXFP8。
* `columnwise_source="original"`：两个方向分别量化原 tensor。
* `columnwise_source="rowwise_dequantized"`：先拼接各 expert 的 rowwise 重构结果，再生成 columnwise storage，使后向 operand 与前向实际看到的低比特值一致。
* 原生 FP8/FP8BS/MXFP8/NVFP4 走 `tex.split_quantize`；自定义 quantizer 逐 split 回退到 Python 调用。
* delayed-scaling 的每 expert scale/amax 可以不同，但每个方向的 quantizer family、dtype 和 backend 配置必须在所有 experts 间一致。

关键文件：

* `transformer_engine/pytorch/module/_split_quantization.py`
* `transformer_engine/pytorch/module/grouped_linear.py`
* `tests/pytorch/test_hybrid_quantization.py`

[官方提交](https://github.com/NVIDIA/TransformerEngine/commit/576b215f90ff97d101b5ea09e9af7ab78cb74663)

局限：不能按 expert 混用 NVFP4/MXFP8 或 quantized/Identity backend；`rowwise_dequantized` 会产生 dequantize→concatenate→requantize 的高精度中间流量。提交没有给出显存或 step-time 对比。

### 4. CUDA Graph `noop` 语义覆盖 FP8、MXFP8、NVFP4 和 4over6

8 月 14 日，TE 修正多个量化 kernel 在 CUDA Graph replay 中忽略 `noop_flag` 的问题。此前被标记为无效的 replay 仍可能覆盖 data、scale 或 amax buffer。

代码修复集中在：

* `common/cast/fp8/quantize_fp8.cuh`
* `common/cast/fp8_blockwise/group_quantize_fp8_blockwise.cuh`
* `common/cast/mxfp8/{quantize,group_quantize}_mxfp8.cuh`

新的 graph 测试检查 rowwise、columnwise 和双向 storage，覆盖 FP8 delayed/current、FP8BS、MXFP8、NVFP4、row-scaled NVFP4，以及 `nvfp4_4over6`；切换 `noop=1` 后，packed data、transpose、scale、amax 必须保持不变。[官方提交](https://github.com/NVIDIA/TransformerEngine/commit/172bd93773ad6ee4ba44b460b7f10ef42fc89d57)

重要例外：融合 dbias 时不能直接跳过 quantization kernel，因为后续 reduction 会读取其 workspace；这些变体会忽略 `noop` 并完成必要写入。这是正确性修复，不代表空 replay 的全部计算都被消除。

### 5. 两个分布式 Wgrad/MXFP8 精度缺口关闭

Megatron 8 月 18 日修正 GTP rematerialization 下的 Wgrad dtype：

```text
BF16 operands
  → Wgrad GEMM epilogue 输出 FP32
  → FP32 reduce-scatter
  → FP32 main_grad
```

此前即使启用 `--accumulate-allreduce-grads-in-fp32`，未融合的 GTP Wgrad 仍可能先生成 BF16 tensor，再做 reduce-scatter，跨 rank 求和前已经发生舍入。新 `_wgrad_gemm()` 在 TE 可用时用 `out_dtype=main_grad.dtype`；同时禁用多余的 FP32-accumulation RS 变体，避免每个 in-flight collective 再分配一个完整未分片 Wgrad scratch。[Megatron 官方提交](https://github.com/NVIDIA/Megatron-LM/commit/e5542e85f294fc215f2e08b3c7e17213f0ffae93)

另一个 TE 修复处理 FSDP rank 没有任何 MXFP8 master-weight shard 的情况：空 rank 现在从 model weight 初始化 amax-buffer dtype，仍参加 MAX all-reduce，并得到与 owner rank 一致的 rowwise/columnwise E8M0 scale。此前会在 collective 前报 `UnboundLocalError`，也存在 dtype 不一致风险。[TE 官方提交](https://github.com/NVIDIA/TransformerEngine/commit/57896b0f3dace49af31bfa873f53de3db86c3069)

局限：GTP 测试是 4-GPU BF16 Linear，并未覆盖 FP4 operands；它保护的是 Wgrad 输出及 collective 精度，而不是乘法输入精度。MXFP8 测试只覆盖 BF16 model dtype 和很小的 `128×128` 权重。

### 6. Nemotron NVFP4 QAD 的官方拓扑被实质修正

上周发布的 Nemotron-3.5-Lightning QAD launcher 会 OOM，而且 `TP=2` 与其 `TP=1` static-NVFP4 PTQ checkpoint 不兼容。8 月 14 日更新为：

```text
4 nodes × 4 B200
TP=1, CP=4, EP=4, ETP=1, DP=1
sequence length=32K
```

`CP=4` 将每 rank token 数限制为 8K，使未分块的 full-vocabulary KL loss 能放入显存；注释中此前声称的 524,288 sequence-length 最终运行也被删除。[官方配置修复](https://github.com/NVIDIA/Model-Optimizer/commit/5e887aa7c931b8950e43b718f0c5ab3bd5427696)

这证明当前 static-NVFP4 QAD checkpoint 对 TP topology 有实际约束。提交没有附完整训练成功记录或新质量结果，因此不能把新配置理解为已验证的性能最优方案。

## Worth testing

* 在 ModelOpt Dual-LSQ 基线上实现 QUASAR-style scale search：复用 Adam `exp_avg_sq`，扫描 `0.30:0.05:1.00`，比较 max、MSE、LSQ 和 loss-aware WLS 的每层 KL、scale 分布及额外耗时。
* 在 B200 上确认 grouped row-scaled Wgrad 命中逐 expert `general_gemm`；记录 kernel 数量与真正 grouped NVFP4 路径的吞吐差距。
* 对 HybridQuantizer 比较 `original` 与 `rowwise_dequantized` column source，测 `dW` bias/cosine、临时 BF16 流量和峰值显存。
* CUDA Graph replay 中交替设置 `noop=0/1`，对 FP8BS、MXFP8、NVFP4、4over6 的 data/scale/amax 做 hash；带 dbias 时另外验证 reduction 没读到旧 workspace。
* 在 GTP 中 hook `wgrad_reduce_scatter`，断言 FP32 `main_grad` 对应的 wire tensor 也是 FP32；再比较 BF16-first 与 FP32-epilogue 的跨 rank 梯度误差。
* 为 MXFP8 FSDP 构造多个连续空 shard rank，检查 collective dtype、row/column scale 一致性，并跑至少数百步确认没有偶发 hang。
