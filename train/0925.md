## 低比特训练技术简报｜9 月 18—25 日

本周没有新的 MXFP4 预训练结果，也没有新的原生 FP4 Fprop/Dgrad/Wgrad 收敛 recipe。高信号进展集中在 FP8 状态管理、RL clipping、4over6 kernel、NVFP4 stochastic rounding，以及 MXFP8 分布式权重数据流。

### 1. QEffect：CUDA Graph 必须显式管理 scale、Wgrad work 与 weight cache

新论文指出，普通 tensor dependency graph 无法表达低精度流水线的四种状态：

- delayed-scaling 的 scale/amax 更新顺序；
- 非 LIFO 延迟 Wgrad 的所有权和生命周期；
- optimizer step 后 quantized-weight cache 的版本；
- caller stream 与 graph stream 的双向完成关系。

其 split-backward 语义是：`dI`（Dgrad 阶段）只更新一次 backward scale state，并产生带 generation 的 Wgrad task；之后的 `dW` 只能消费该 task，不得再次修改 scale。`TapeKey/TapeRef` 防止复用 slot 的 ABA 问题，weight/cache epoch 防止 optimizer 后读到旧量化权重，双向 CUDA event 则补齐 graph replay 的 happens-before。

论文报告：无约束异步路径的 600 次检查全部出现 stale read；加入合约后保持与原生 TE full backward 的逐位一致。H800 上 graph capture 相对 eager 为 `1.82–2.79×`，直接把 Wgrad 写入稳定的 `main_grad` arena 又减少每 rank 每 step 96 次 copy，并带来额外 `1.132×`。[论文](https://arxiv.org/html/2609.23536)

限制：基于 TE 2.18、四层模型、sequence 256、单节点 H800/Ada；没有 FP4、MoE 或多节点实验，也没有公开实现仓库。graph 数量和 gradient arena 容量均随 microbatch 数线性增长。

### 2. Calibrated Clipping 定位 full-pipeline FP8 RL 的新失稳机制

论文发现，policy probability 的单次 FP8 误差在 importance ratio 中会放大 `1.7–2.9×`。训练后期约 70% 的错误 clipping 发生在下界，其中近 90% 来自高熵 response：负 advantage token 被错误推到下界以下，梯度归零，模型无法消除已经出现的乱码行为。

Calibrated Clipping 每 20 step 执行两次 BF16 forward-only shadow pass：

1. 对负 advantage token，使 FP8 下界 clipping quantile 与 BF16 对齐；
2. 搜索上界，使正、负 update contribution ratio 与 BF16 相同。

实现参数为：

```text
lower search: [0.5, 0.9]
upper search: [1.2, 2.0]
step: 0.02
initial bounds: [0.6, 1.8]
max update: lower 0.05 / upper 0.1
```

Qwen3-8B GRPO 的 blockwise FP8 平均分从 `54.1` 恢复到 `58.6`，BF16 为 `57.6`；Qwen3-14B DAPO 从 `41.6` 恢复到 `47.4`，BF16 为 `50.9`。Tensorwise FP8 的训练阶段吞吐最高为 BF16 的 `1.5×`。[论文](https://arxiv.org/abs/2609.22870)

重要限制：吞吐测试排除了周期性 BF16 shadow pass，不能视为端到端速度；结果只覆盖 token-level GRPO/DAPO。固定把下界从 `0.8` 放宽到 `0.6` 虽能阻止 entropy surge，却造成过度负更新和较差 reward。

### 3. TE 将 NVFP4 4over6 改为按 GPU 架构运行时编译

9 月 24 日，Transformer Engine 将原本约 384 种静态模板组合的 4over6 quantization 改为 NVRTC JIT，并针对实际设备编译精确的 `sm_XXXa` kernel。

数值算法保持不变：每个 16-value group 同时计算 map-to-6 与 `1.5× scale` 的 map-to-4 候选，按 MinMSE 或 MinMAE 选择，误差相同则选 map-to-6。两套 FP4 codes、反量化值和误差都保存在寄存器中。

关键位置：

- `common/cast/nvfp4/quantize_4over6_kernel.cuh`
- `common/cast/nvfp4/rtc_dispatch.cpp`
- `common/cast/nvfp4/rtc/quantize_4over6.cu`

默认 `NVTE_BUILD_LEGACY_STATIC_NVFP4=OFF`。若设置 `NVTE_DISABLE_NVRTC=1`，必须重新构建并启用该选项，否则 4over6 会直接报错。[官方提交](https://github.com/NVIDIA/TransformerEngine/commit/ec39dcf368920d3be1e9d5ae6a5604226fcc939b)

限制：4over6 仍不支持 stochastic rounding，只输出 compact scale；row-scaled 模式不能与 2D/columnwise 同用，相关维度须被 16 整除。没有公布首次 JIT 延迟、build-time 或训练吞吐数据；这是 kernel 部署变化，不是新的 scale-quality 结果。

### 4. NVFP4 row/column stochastic rounding 曾持有悬空 RNG buffer

9 月 23 日，TE 修复 `NVFP4Quantizer` 的 RNG 生命周期错误。此前 rowwise 与 columnwise 同时启用 RHT+SR 时，两份 Philox seed/offset tensor 是局部变量；`TensorWrapper` 不拥有底层 storage，异步 quantization dispatch 可能在 RNG buffer 已被 allocator 回收后才读取它。

修复后，两份 `at::Tensor` 会一直存活到 dispatch 完成。新增测试覆盖 32/64/96/128 列、allocator fragmentation、RNG state restore，并要求 row/column data、scale 和 amax 对同一 seed 逐字节一致。[官方修复](https://github.com/NVIDIA/TransformerEngine/commit/0b87832b43e74b4793eb8f7e9dc833e3ff4bc063)

这不是 stochastic-rounding 算法变化，而是确定性和内存安全修复。旧路径可能让 Wgrad 使用的 columnwise operand 随 allocator 历史变化；官方尚未报告实际训练中的发生频率或 loss 影响。

### 5. Megatron MFSDP v2 开始原生保存 MXFP8 的四个物理平面

Megatron 现在为 MXFP8 weight group 使用 `BlockAtomic(32)` 分片，并引入 `QuantizedDBuffer`：

```text
rowwise FP8 data
columnwise FP8 data
rowwise UE8M0 scale
columnwise UE8M0 scale
```

FP32 master weight 从 `get_high_precision_init_val()` 初始化；optimizer step 后通过 `post_optimizer_model_weight.quantize_(main_weight)` 刷新四个平面。distributed storage 保存 compact scale，materialize 给 TE GEMM 时再补 padding。

测试覆盖 Zero-2、Zero-3 和无分片，在 GB200 上验证四平面与 TE reference 一致，短 MLP 训练 loss 与独立 reference 的绝对差不超过 `3e-3`。[MFSDP MXFP8 集成](https://github.com/NVIDIA/Megatron-LM/commit/85cda9247bc5ea0afe2bc6e5207839115d10e2f9)

同周还补齐 MXFP8 grouped-MoE 的 batch-invariant forward：训练使用 `batch_invariant_backend="te_native"`；SM100 + cuBLASLt 13.5.1 可用 `moe_use_grouped_tensor=True`，但需要每 expert 256-row padding并关闭 TE op fuser。Squared-ReLU 会先按 BF16 舍入再量化，SwiGLU 则保留独立 BF16 activation 与 MXFP8 cast。[batch-invariant MXFP8](https://github.com/NVIDIA/Megatron-LM/commit/5f51602f059a1bda38ee64bf676bf9a4bda96339)

限制：当前 forward 和 backward 阶段都会 all-gather rowwise、columnwise data 与两套 scale，通信和临时存储尚未按 Fprop/Dgrad 分离；scale padding也会额外分配和复制。batch invariance 只承诺 forward，不保证不同 minibatch 的梯度逐位一致。

### 6. Aumann–Shapley scale/format allocation 已进入 Model Optimizer

ModelOpt 新增：

```python
method="aumann_shapley"
method_options={
    "num_path_nodes": 2,
    "damage_link": "coverage",
    # 或 "max_predicted_damage": 0.05
}
```

它不需要标签：先保存 baseline next-token distribution，然后在 `y + t(Q(y)-y)` 的多个路径节点上，用 KL gradient 为每个 runtime group 和候选格式分配 damage。solver 可在固定 `effective_bits` 下最小化预测损伤，也可在 damage 上限下自动选择最小 bit width。

实现位于 `modelopt/torch/quantization/_auto_quantize_shapley.py`。在 NVFP4/FP8、约 6-bit 配置中，Qwen2.5-0.5B 的路径贡献解释了直接测得最低精度 KL 的 98%，Qwen3-30B-A3B 为 99%；官方称该方法已用于 Kimi-K3、MiniMax-M3 和 GLM-5.2 的 NVFP4 checkpoint。[官方实现与结果](https://github.com/NVIDIA/Model-Optimizer/commit/63c4b660bdd51669a7d66fc06742a8475c719d2e)

限制：这是 PTQ format allocation，不是低比特反向训练；没有任务精度或相对 Local-Hessian/4over6 的统一实验。目前也不支持 vocab-sharded Megatron TP loss，正式 recipe integration 尚未加入。

另外，上周的 per-expert scale 重分片仍漏掉“TP 和 EP 同时大于 1”的保存路径；9 月 24 日的补丁才正确传入 expert TP/DP process groups，并在 TP2/EP4 的 8×B200 配置上完成 checkpoint 保存。[checkpoint 补充修复](https://github.com/NVIDIA/Model-Optimizer/commit/ed7e87953c1a3ed6a21c8bf6eac90565fa6b7a36)

## Worth testing

- 对 split backward 刻意打乱 Dgrad/Wgrad 顺序，记录 scale epoch、tape generation、weight-cache epoch 和 stream event；验证 graph replay 与 eager 逐位一致。
- 在 FP8 RL 中按 advantage 正负分别统计 BF16/FP8 ratio error 与 clipping quantile；把两个 BF16 shadow pass计入端到端吞吐。
- 对 4over6 NVRTC/static 路径比较 packed data、scale 和 MinMAE/MinMSE 决策，并分别测 cold-JIT 与 warm replay 延迟。
- 固定 seed、制造 CUDA allocator fragmentation，hash NVFP4 row/column data、scale、amax 及最终 Wgrad。
- 用 profiler 量化 MFSDP 当前四平面 all-gather 与 scale-padding copy；原型比较“Fprop 只传 rowwise、Dgrad 只传 columnwise”。
- 在同一 calibration tokens 和 bit budget 下比较 Aumann–Shapley、Local-Hessian、MSE 与 4over6：同时记录预测 KL、实测 KL、任务分数及 MoE expert token coverage。
