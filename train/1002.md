## 低比特训练技术简报｜9 月 25 日—10 月 2 日

本周最重要的新结果是 FP8 attention 的 backward 一致性修正，以及两项可直接改变 NVFP4 scale/QAD 实现的工作。没有新的 4over6 训练结果。

### 1. Delta-Matching：修正原生 FP8 attention 的 stale-delta

FP8 attention 常复用前向输出计算 softmax backward 的行修正量：

\[
\delta_i^{stale}=\langle dO_i,\widehat O_i\rangle
\]

但 backward 实际使用量化后的 \(\widehat{dO},\widehat V\) 计算 \(\widehat{dP}\)，且前向使用量化概率 \(\widehat P\)。这种不一致会破坏：

\[
\sum_j dS_{ij}=0
\]

Delta-Matching 改为用未量化的 FP32 概率和实际 FP8 backward operands 的 FP32 product 计算：

\[
\delta_i^{matched}=\sum_j P_{ij}\widehat{dP}_{ij}
\]

实现中额外遍历 key tiles，以 FP32 reduction、FP64 accumulator 求 correction；七个 attention-core matmul 仍全部使用 FP8。[arxiv.org](https://arxiv.org/html/2609.37852v1?utm_source=chatgpt.com)

**已证明：**5.29B、30B-token 训练中，naive FP8 的验证 CE 为 `1.9327`，BF16 为 `1.3349`；Delta-Matching 为 `1.3374`。RULER-8K 分别为 `16.3 / 53.5 / 58.6`。64K context extension 中 Delta-Matching 为 `45.6`，BF16 为 `46.0`；一个 cuDNN/TE FP8 seed 发散。[arxiv.org](https://arxiv.org/html/2609.37852v1?utm_source=chatgpt.com)

**限制：**cast 后仍会重新引入 row-sum residual；recurrent layers、output head、softmax 和 reductions 仍为高精度。代码仅承诺未来发布，目前没有可复核仓库。[论文](https://arxiv.org/abs/2609.37852)

### 2. QATFactory：NVFP4 与 MXFP4 不应复用同一 QAD recipe

QATFactory 在 BF16 GEMM 上模拟部署格式，因此 H100 也能进行 NVFP4/MXFP4 fake-quant QAD。它支持 dense/MoE、full-parameter/LoRA、QAD/QARL，并直接导出 vLLM 或 llama.cpp 格式。

最有用的结果是格式相关的 recipe：

- NVFP4：训练时通常只 fake-quant weight 更好，即使最终部署为 W4A4。
- MXFP4：训练时同时 fake-quant weight 和 activation 更好。
- 固定 token budget 时，较少的 32K sequences 比更多 4K sequences 平均高 `1.9` 分。
- Qwen3.5-9B：NVFP4 QAD `68.9`，最佳 PTQ `65.4`；MXFP4 为 `66.0` 对 `56.4`。[arxiv.org](https://arxiv.org/abs/2609.39223?utm_source=chatgpt.com)

**限制：**这不是原生 FP4 Fprop/Dgrad/Wgrad，训练加速不能从结果推出。论文声称发布完整代码，但其指向的 [QATFactory 仓库](https://github.com/QATFactory/QATFactory) 在本次核查时仍不可访问，因此具体配置和 exporter 尚无法审计。[论文](https://arxiv.org/abs/2609.39223)

### 3. Schur Replay：在 GPTQ recurrence 中选择 NVFP4 scale

普通 scale sweep 独立评估每个 16-weight block，但 GPTQ 会在量化一列后补偿后续列，所以初始 block MSE 不等于最终误差。

Schur Replay：

1. 使用 conditional curvature  
   \[
   S_G=H_{GG}-H_{GF}H_{FF}^{-1}H_{FG}
   \]
   只惩罚未来未量化列无法补偿的误差。
2. 做三次 fixed-code scale 更新。
3. 在实际 E4M3 scale grid 附近取默认十个候选。
4. 对每个候选完整重放 16 列 GPTQ recurrence，再提交最低 Schur score 的 scale。[arxiv.org](https://arxiv.org/html/2609.36654v1?utm_source=chatgpt.com)

Qwen3.5-397B-A17B W4A4 的七任务加权 BF16 recovery 为 `99.35%`，4over6+GPTQ 为 `97.32%`；Llama-3.3-70B 为 `100.84%` 对 `99.14%`。[arxiv.org](https://arxiv.org/html/2609.36654v1?utm_source=chatgpt.com)

**限制：**这是 PTQ，不涉及训练反向。397B 完整耗时是按 layer type 推算；论文的 `15.17×` 不包含 Schur Replay 自身的额外搜索时间。ModelOpt patch 仅承诺论文接收后发布。[arxiv.org](https://arxiv.org/html/2609.36654v1?utm_source=chatgpt.com) [论文](https://arxiv.org/abs/2609.36654)

### 4. ModelOpt 修复 NVFP4 fake-quant 对小 scale 静默清零

动态 Triton `fp4_fake_quant_block` 和 Conv3D implicit-GEMM 路径曾把所有 `<1e-5` 的 E4M3 block scale 替换为 `1.0`。结果是 `max|x| ≲ 6e-5` 的 block 整块变零；static Triton、CUDA extension 和 export 路径不受影响。

修复后：

- 复用 `nvfp4_scalar_quant`；
- 只有 scale 精确为零才清零 block；
- E4M3 subnormal scale 被保留；
- global amax 为 `0/Inf/NaN` 时采用 unit block scale，与 CUDA extension 对齐；
- 新测试验证输入与 amax 同时乘 `2^-10`、`2^-20` 时，输出严格同比缩放。

这会改变受影响 QAT/QAD checkpoint 的训练数值，但不会改变原生 Blackwell Tensor Core GEMM。[官方提交](https://github.com/NVIDIA/Model-Optimizer/commit/834c90d7a1e48da28fae8c6611418241074c4fd0)

### 5. TE 扩展 NVFP4 cast：双向 amax 融合与 SM120/121 RHT

10 月 1 日，row-scaled NVFP4 将 rowwise/columnwise 两次 amax 扫描融合为一个 TMA kernel：一次把 `128×128` tile 搬进 shared memory，同时生成两个方向的 amax。Grouped-MoE 版本则从“每 expert 一次 launch”改为 packed `(sum_M,K)` 的单 launch。

相关位置：

- `common/cast/nvfp4/quantize_transpose_nvfp4.cuh`
- `common/cast/nvfp4/group_quantize_transpose_nvfp4.cuh`
- C API：`nvte_group_nvfp4_compute_amax`

dense 快路径要求 BF16、维度 128 对齐；grouped 入口现在会显式拒绝未对齐的 `K`，避免静默遗漏尾列。另一个同步修复确保 CUDA Graph `noop` 不会清空既有 amax。这优化的是供 Fprop/Wgrad 使用的量化准备，不改变 GEMM accumulator。[dense 提交](https://github.com/NVIDIA/TransformerEngine/commit/a16bce3a647e4277b78c6426e70b9c6d4a1135dd)、[grouped 提交](https://github.com/NVIDIA/TransformerEngine/commit/b57646c288c07ae11034a59919ff1cdf795d15f8)

同时，SM120/121 新增 fused NVFP4 RHT cast：TMA 搬运、K16 WMMA Hadamard、register 内 stochastic rounding，并验证与 TE unfused K16 reference 的 data、scale、post-RHT amax 逐位一致。可用 `NVTE_NVFP4_DISABLE_RHT_CAST_FUSION=1` 做回退；SM12x 暂不支持 GEMM-swizzled scale。[RHT 提交](https://github.com/NVIDIA/TransformerEngine/commit/177025965c7ad0b1078d278fabbb4eb972c3bca2)

**限制：**三个提交都没有 kernel latency 或端到端 step-time 数据；RHT 更新不影响 B200/SM100。

### 6. 两个 grouped-MoE Wgrad 生命周期错误被关闭

TE 的 `GroupedLinear` 新修复了两条独立路径：

- `DistributedWeight` grouped-tensor backward 不再捕获短命的 gathered tensor；现在保存原始 shard，backward 重新 gather，BF16 shard 在 FP8/MXFP8 recipe 下重新量化供 Dgrad，并通过原 shard 的 `grad_buffer`/`finalize_weight_grads` 提交 Wgrad。这样也不会长期保留完整 unsharded weight。[DistributedWeight 修复](https://github.com/NVIDIA/TransformerEngine/commit/45de18a6ba5ebedb26dfb7b3b210ec26ef5d47d9)
- cuDNN frontend 1.30 的 grouped Wgrad 新增持久 `descriptor_workspace`。FC1 与 FC2 即使 workspace 大小相同也必须各自缓存；共用会损坏 weight gradients。持久 workspace 同时避免因 Wgrad output pointer 改变而重复编译、阻止 CUDA Graph capture。[cuDNN Wgrad 修复](https://github.com/NVIDIA/TransformerEngine/commit/0cc62eccbde3d56bcaf5fc9c677ebc6cc690039c)

**限制：**现有证明主要是单元测试，没有大模型 loss、逐 expert Wgrad hash 或 graph replay 性能数据。

## Worth testing

- 在 FP8 attention 中记录 `sum(dS, dim=-1)`、Q/K gain product 和 cast 前后 residual；不要只比较短期 loss。
- 对 QATFactory 思路做 `NVFP4 W-only`、`NVFP4 W+A`、`MXFP4 W-only`、`MXFP4 W+A` 四组同 token 对照，并用真实部署 checkpoint 评估。
- 将 Schur Replay 的十候选 recurrence replay 接到现有 4over6/GPTQ，实现同 calibration tokens 的 answer-level 配对比较。
- 对极小 activation 注入 `2^-10/2^-20` 缩放，确认 ModelOpt fake quant 不再整块归零。
- 对 fused/unfused amax 比较 row/column amax bytes、packed FP4、CUDA Graph `noop` 后状态和 kernel 时间。
- 在 grouped MLP 中分别 hash FC1/FC2 Wgrad workspace 地址与 gradient；DistributedWeight 路径同时检查 Fprop gather、Dgrad requantize 和最终 shard `main_grad`。
