# 低比特训推与加速器技术周报

2026年11月6日—11月13日

本期最值得关注的是：缓存压缩开始同时优化误差与解包成本，训练侧则提醒我们，损失接近不一定意味着知识学习同样高效。框架正在补齐量化接口、缩放布局与硬件执行之间的连接；阅读“支持某格式”时，仍应区分存储表示、转换过程和真正执行的矩阵指令。

优先推荐 FP4 稀有事实学习研究、BitDecoding-FP4 与 FOSCAR，以及 AMD 关于缓存容量和并行策略的新测量。PyTorch 的公开量化接口和不同平台的低比特软件适配，也值得持续关注。

## 硬件与加速器

- [重点推荐：MI300X 新测量解释 FP8 缓存何时增加吞吐](../gpu/20261113.md#amd-cache-parallel)：11 月 11 日官方文章比较 GLM-5.3-Flash 在八卡 MI300X 上的张量并行，以及数据并行加专家并行。
- [MI355X：FP8 缓存、通信与前缀复用一起优化](../gpu/20261113.md#amd-mi355x-prefix)：11 月 11 日官方文章展示八卡 MI355X 上 GLM-5.2 FP8 的服务优化，包括上下文并行、AITER 稀疏注意力、FP8 缓存以及带缩放数据的通信。
- [AITER：MiniMax 稀疏索引读取 NVFP4 键缓存](../gpu/20261113.md#aiter-nvfp4-index)：gfx950 的 MiniMax-M3 稀疏注意力索引器新增四比特键缓存的解码与预填充评分路径。
- [VisualGen 新博客：组合优化中的 FP4 收益应单独看](../gpu/20261113.md#nvidia-flux3)：11 月 6 日官方教程介绍 FLUX 3 Image Klein 在 TensorRT LLM VisualGen 中的 FP8／NVFP4、编译、注意力与缓存优化。
- [FlashInfer：SM120／121 原生 NVFP4 MoE 扩展](../gpu/20261113.md#flashinfer-sm12x-moe)：新增原生 CuTe DSL 混合专家（MoE）算子，涵盖路由、分组矩阵乘、激活再量化和输出合并，同时保留既有后端与打包权重接口。
- [oneDNN：两比特权重配 INT8 激活进入 GPU 路径](../gpu/20261113.md#onednn-u2-s8)：Intel GPU 的矩阵乘实现增加无符号两比特权重与八比特激活的组合，执行前把权重提升为有符号八比特。
- [TPU Sync：直接搬运设备布局的缓存与权重](../gpu/20261113.md#tpu-sync)：11 月 9 日官方开源介绍将 TPU 显存、主机内存、存储和网络作为统一的状态搬运层，以异步直接内存访问让传输与计算重叠。
- [FlashAttention：MXFP8 查询键乘法配 BF16 概率值乘法](../gpu/20261113.md#flashattn-mxfp8-qk)：新增 MXFP8 分块缩放的查询×键前向路径，概率×值部分保留 BF16，注意力分数与 softmax 统计仍使用 FP32。

## 训练与后训练

- [重点推荐：FP4 的损失曲线可能掩盖稀有事实学习变慢](../train/20261113.md#rare-fact-fp4)：《What the Loss Curve Misses》用可控出现次数的合成人物传记及混合网页文本，研究四比特预训练学到知识的效率。
- [Transformer-FSQ：训练离散瓶颈，改变缓存表示](../train/20261113.md#transformer-fsq)：用有限标量量化（FSQ）瓶颈替换普通键值投影，把每个 token 的缓存存成打包整数码，不再附带逐 token 量化元数据。
- [重点推荐：MXFP8 单向与双向量化进入公开接口](../train/20261113.md#pytorch-quantize-api)：新增 F.quantize_tensor 与 F.quantize_tensor_dual，分别产生单方向或两个转置方向的量化数据和缩放，供训练前反向使用。
- [按行缩放 NVFP4 从量化扩展到分组矩阵乘](../train/20261113.md#te-rowscale-gemm)：此前的分组量化本周接上实际分组 GEMM（矩阵乘），覆盖前向与权重梯度，并补齐缩放因子的交错布局。
- [UE5M3 缩放的 NVFP4 接入 cuBLAS](../train/20261113.md#te-ue5m3-cublas)：常规和分组矩阵乘增加 UE5M3 缩放类型，替换原先借助 cuDNN 包装器的临时路径。

## 推理与部署

- [重点推荐：BitDecoding-FP4 把误差控制与原生 FP4 解码一起设计](../inference/20261113.md#bitdecoding-fp4)：将查询拆成两个 FP4 张量表示残差，针对长上下文概率下溢调整缩放，并用平滑与正交旋转处理键的异常值。
- [FOSCAR：减少 INT2／INT4 缓存的反量化指令](../inference/20261113.md#foscar)：把逐缓存值的缩放与偏移运算折叠到注意力矩阵乘的另一个操作数或结果端，降低解码中的指令压力。
- [ROCm 稀疏潜在注意力增加 MXFP4 缓存读写](../inference/20261113.md#vllm-mxfp4-mla)：新增 mxfp4_mla 缓存格式，将潜在键值按每 32 个数共享缩放的方式打包，覆盖写入、寻址与读取。
- [把激活函数与下一层 NVFP4 量化合并](../inference/20261113.md#sglang-silu-nvfp4)：将 SiLU 激活与门控相乘后直接生成下一线性层需要的 FP4 数据和缩放，减少中间张量及重复量化。
- [FP8 从基础格式扩展到缓存与 CUDA 执行](../inference/20261113.md#llamacpp-fp8-kv-cuda)：继此前基础格式支持后，本周新增带缩放的 FP8 键值缓存，并接入 CUDA 的转换、访存、矩阵向量乘与注意力路径。
- [冷缓存压缩保留首尾 token 的运行时精度](../inference/20261113.md#trt-cold-mixed)：新增首 N 个与最近 N 个 token 的混合精度保留选项，仅压缩中间历史的冷页。
- [v1.4.0rc3：NVFP4 缓存仍有模型正确性边界](../inference/20261113.md#trt-rc3-kv-correctness)：本周候选版扩展若干低比特模型路径，同时明确列出：包括 GLM-5.2 在内的 DSA 稀疏注意力模型使用 NVFP4 缓存可能产生错误输出。
- [递归残差量化：同一 checkpoint 按需选择位宽](../inference/20261113.md#autoround-rrq)：实验性接入递归残差量化（RRQ），把权重分成两比特基底与多个残差平面，加载时选择 2／4／6／8 比特或逐层混合精度。
- [Arm 打包的低比特线性层现在可在 x86 执行](../inference/20261113.md#torchao-x86-lowbit)：把原先会抛错的 x86 回退路径补成可执行实现，读取与 Arm 相同的低比特权重布局，并覆盖查表编码。
- [昇腾 INT4／INT8 推理反量化恢复可用](../inference/20261113.md#deepspeed-ascend-dequant)：修复昇腾 NPU 后端缺失的 INT4／INT8 到 FP16 反量化入口，按 DeepSpeed 的高半字节优先布局恢复权重。
