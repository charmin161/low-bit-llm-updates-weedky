# 低比特训推与加速器技术周报

2026年10月30日—11月6日

本期值得关注的变化是：低比特训练开始更明确地处理前反向与生成路径的一致性；缓存压缩进一步覆盖稀疏索引和循环维；底层实现则需要把数据值、缩放表示与实际指令一起核对。四比特存储不自动等于四比特计算，单算子收益也不能直接外推到整个服务。

优先关注 FLAMIA、Megatron 的训推一致性、LoopVQ，以及 Rubin 的 NVFP4_PLUS 路径。AMD 的分页注意力、通信融合与 Ryzen AI NPU 部署展示了不同平台的实现选择；Intel 的分组矩阵乘仍处于分阶段接入。

## 硬件与加速器

- [重点推荐：TensorRT-LLM 接入 NVFP4_PLUS MoE](../gpu/20261106.md#nvfp4plus)：新路径使用 E2M1 四比特值，每 32 个值配一个 UE5M3 缩放因子，取消 FP32 全局缩放。
- [Kimi K3.1 Pro 官方技术文章：原生 FP4 索引计算](../gpu/20261106.md#amd-kimi)：AMD 新文章解释 MI355X 上 ATOM 与 vLLM 的低比特实现。
- [AITER：MXFP4 分页 KV 解码接入共享注意力内核](../gpu/20261106.md#aiter-kv)：新增 gfx950、单查询 token 的分页注意力解码路径，读取 E2M1 数据与每 32 元素一个 E8M0 缩放。
- [AITER：CDNA4 增加 MXFP8 注意力前向与反向](../gpu/20261106.md#aiter-mxfp8)：新增面向 gfx950／CDNA4 的 MXFP8 Flash Attention v2 实现，提供前向、反向及携带块缩放的 Python 接口。
- [MoRI：将 all-gather 与消费数据的 FP8 GEMM 融合](../gpu/20261106.md#mori)：新增融合算子把各设备的 token 聚合与后续 FP8 矩阵乘衔接起来，本地块先算，远端数据分块到达后再消费，缩放因子随数据一起传输。
- [INT4 基座配动态 LoRA：一个 NPU 模型服务多个适配器](../gpu/20261106.md#ryzen)：官方新博客介绍 Ryzen AI 1.9 的动态 LoRA 流程：以 Quark 将基座量化为 INT4 AWQ，针对冻结基座训练并保留独立适配器，编译后运行时切换。
- [PyTorch 接入 oneDNN 分组低比特矩阵乘底层](../gpu/20261106.md#intel-grouped)：主分支合入 Intel XPU 分组矩阵乘的 oneDNN 集成部分，面向 FP8、MXFP8、MXFP4 和 NVFP4 等类型。

## 训练与后训练

- [FLAMIA：兼顾因果安全与前反向一致性的低比特注意力](../train/20261106.md#flamia)：。
- [FP4Quant：把模型并行通信压到四比特](../train/20261106.md#fp4quant)：通过微分组双尺度量化、线程束协作打包，以及快速 Walsh–Hadamard 变换分散异常值，降低通信字节数并控制压缩开销。
- [重点推荐：MXFP8／NVFP4 MoE 的训练前向对齐生成路径](../train/20261106.md#megatron-parity)：主分支加入可选的训练前向路径，复用生成端 FlashInfer 专家内核、路由顺序与合并算术，覆盖 MXFP8 和逐 token NVFP4。
- [BatchedLinear：补齐 BF16／MXFP8 批量矩阵乘](../train/20261106.md#te-batched)：新增带步幅的批量 GEMM（矩阵乘）和 PyTorch BatchedLinear，将一组线性计算接入 BF16／MXFP8 路径，并依据张量的批次维推断布局。

## 推理与部署

- [重点推荐：LoopVQ 利用循环维冗余压缩 KV 缓存](../inference/20261106.md#loopvq)：LoopVQ 把循环 Transformer 多次循环的键值缓存联合编码，让一个码本索引服务多个循环步骤，并按输出误差优化码本。
- [Beyond Accuracy：量化后的编程代理行为也要看](../inference/20261106.md#agent-quality)：研究比较 Qwen2.5-Coder 与 Devstral 的 BF16、四比特 AWQ／GPTQ，在 OJBench 上观察多轮编程与工具调用。
- [Kimi K3.1 Pro：低比特潜在缓存与索引缓存协同](../inference/20261106.md#vllm-cache)：官方新博客说明，注意力的潜在键值缓存可选 NVFP4，稀疏索引键可独立选 MXFP4，压缩布局可用于预填充与解码分离传输。
- [MXFP4 输入旋转与 Quark 导出模型接通](../inference/20261106.md#vllm-rotation)：主分支合入按块 Hadamard 正交旋转的线性层包装器，支持在线 MXFP4 量化及已带旋转信息的 Quark checkpoint。
- [Engram 查表保留 MXFP4 打包，减少主机内存](../inference/20261106.md#sglang-engram)：DeepSeek-V4.1 的 Engram 表加载后保持四比特打包，查表时再解码，避免提前扩成 FP8。
- [v0.9.0：OCP FP8 E4M3 进入正式版本](../inference/20261106.md#llamacpp-release)：上期跟踪的 OCP FP8 E4M3 基础格式本周进入 v0.9.0 正式发布，并随 ggml v0.29.0 提供相应格式支持。
- [张量并行与低秩适配扩展量化调优路径](../inference/20261106.md#autoround)：主分支加入张量并行配置与 LoRA 低秩参数支持，并调整 FP4 混合专家模型的调优实现。
