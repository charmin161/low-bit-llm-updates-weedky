# 低比特训推与加速器技术周报

2026年11月13日—11月20日

本期值得关注的变化是：低比特方案开始更认真地处理训练、导出与实际执行之间的数值一致性。CertiSum 研究跨平台可复现，Inkling 2 Small 展示贯穿训练阶段的四比特前向，ModelOpt 则修复校准与打包的舍入差异。三者解决的问题不同，不能用单一“支持 FP4”概括。

硬件侧，AMD 公开六比特前向配四比特反向的训练细节；NVIDIA 与 Intel 的注意力底层继续扩展概率侧低精度计算。缓存侧，压缩表示、原生计算、分层搬运正在一起设计，但论文测量、主分支适配与正式版可用性仍需分清。

## 硬件与加速器

- [重点推荐：官方公开 MXFP6／MXFP4 混合训练配方](../gpu/20261120.md#amd-fp6)：AMD 的 MLPerf Training 6.1 技术文章说明，FLUX.1 敏感前向使用 MXFP6，反向矩阵乘使用 MXFP4，并通过 Hadamard 旋转、分块缩放与融合量化适配 CDNA4 原生指令。
- [PyTorch：gfx1250 补齐 MXFP8／MXFP4／NVFP4 缩放布局](../gpu/20261120.md#gfx1250-scale)：主分支新增 gfx1250 所需的缩放交错布局，支持每 32 元素共享缩放的 MX 格式，以及每 16 元素共享缩放的 NVFP4。
- [ATOM 新博客：FP8 缓存还需配合分片与状态复用](../gpu/20261120.md#atom-cache)：11 月 17 日官方机制解读说明，Kimi-K3 的 FP8 潜在缓存与主机缓存、前缀复用、解码上下文并行一起管理，降低长代理会话的显存压力。
- [FlashAttention：MXFP8 前向扩展到概率乘值](../gpu/20261120.md#flashattn-pv)：继上期查询乘键的 MXFP8 路径，本周原生低精度计算进一步覆盖注意力概率乘值，值张量以每 32 个键共享缩放的方式组织。
- [FlashInfer：MXFP8 激活乘 MXFP4 权重保持批次不变性](../gpu/20261120.md#flashinfer-invariant)：新增稠密矩阵乘接口，在显式选择批次不变模式时，使同一输入行的结果不受批大小、行位置和调度配置影响。
- [oneDNN：融合注意力接入 softmax 输出量化](../gpu/20261120.md#onednn-prob)：Intel GPU 的融合注意力实现增加概率量化与反量化缩放，把 softmax 输出到后续值矩阵乘之间的精度转换纳入算子描述与内核。

## 训练与后训练

- [重点推荐：CertiSum 让 MXFP4 训练跨平台逐位一致](../train/20261120.md#certisum)：通过量化时收集统计量，判断原生 FP32 累加是否已精确；无法证明的输出再用精确内核计算，并保持跨并行布局的量化分块一致。
- [重点推荐：Inkling 2 Small 从预训练到强化学习使用四比特前向](../train/20261120.md#inkling)：Thinking Machines 的新技术文章介绍：混合专家层前向采用原生 NVFP4，反向保留 MXFP8，并配合重新量化、随机舍入及通信量化。
- [JAX MoE 增加 MXFP8 token 分发](../train/20261120.md#te-dispatch)：主分支将 MXFP8 数据及其缩放因子接入 JAX 混合专家（MoE）分发路径，减少专家并行传输的数据量，并把量化表示交给后续专家计算。
- [FP4 模型接入独立 MXFP8 输出层与融合注意力量化](../train/20261120.md#megatron-mixed)：FP4 模型现在可将语言模型输出投影单独放进 MXFP8 上下文，避免被全局四比特配置阻止。

## 推理与部署

- [重点推荐：NVFP4-MLA 同时压缩潜在缓存与注意力计算](../inference/20261120.md#nvfp4-mla)：用选择性四比特残差补偿敏感通道，并以二维量化分块适配两次注意力矩阵乘的不同归约方向，避免中途重新量化。
- [MiSTiQ：极低位宽存储直接重建为微缩放格式](../inference/20261120.md#mistiq)：将格形编码与搜索结合，扩大缓存重建空间而不保存巨大码本，再通过 MX-Hash 直接生成目标低精度格式的重建值。
- [QDA：代理搜索可直接部署的量化配方](../inference/20261120.md#qda)：将多种训练后量化方法放进可组合库，由代理反复构建、评估配方。
- [量化草稿缓存：位宽分配要与分组布局一起选](../inference/20261120.md#draft-kv)：《Memory-Efficient Speculative Decoding with Quantized Draft KV Cache》只压缩投机解码草稿模型的缓存，目标模型和验证器保留 BF16。
- [v0.34.0：低比特部署入口与启动缓存正式更新](../inference/20261120.md#vllm-release)：正式版收录多种 FP8、MXFP8、NVFP4 与 AWQ／GPTQ 权重缓存重启路径，减少再次启动时重复处理权重的需要。
- [在线重新量化增加 block-FP8 到 MXFP4，并降低加载峰值](../inference/20261120.md#vllm-requant)：主分支扩展已量化专家权重的在线转换，支持带动态激活量化的 FP8 checkpoint，包括逐张量、逐通道及分块权重缩放。
- [昇腾：FP8／MXFP8 缓存接入主机分层缓存](../inference/20261120.md#ascend-hicache)：HiCache 是将设备缓存扩展到主机等层级的缓存系统。
- [重点推荐：修复 NVFP4 校准与导出在舍入边界不一致](../inference/20261120.md#modelopt-round)：此前动态 Triton 模拟量化与导出打包采用不同的缩放除法，在恰好位于四比特舍入边界时可能选中不同编码。

## 覆盖说明

本期主动检索 NVIDIA、AMD、昇腾、Intel、Google 和 AWS 的官方材料，并检查训练、量化、推理、算子、编译与通信项目。CANN 官方入口显示新社区测试版发布，但公告正文未能提取，无法核实其低比特新增能力；Intel、Google 与 AWS 的检索未取得足以单列的入窗官方新技术文章，不代表没有更新。Intel 底层实现与昇腾框架适配已分别收录。

仓库检索结合定向格式关键词、近期提交抽样及发布说明，没有穷尽高提交量项目。搜索索引可能滞后，纯 INT 量化、缓存与通信中的无格式关键词变更尤其可能遗漏。DeepInfer、DeepGEMM、FlashMLA、DeepEP 与独立 Marlin 仓库未检出入窗新提交，未重复报道历史能力。CANN 公告访问缺口及抽样范围已记入内部索引。

所有性能和质量结果均归于原作者，本期没有运行硬件实验。AMD ATOM 条目是本周新机制解读，引用的性能运行较早；FlashAttention、vLLM 的历史主题只介绍本周新增执行路径或正式发布状态。
