## 论文与方法推荐

<a id="nvfp4-mla"></a>

#### 重点推荐：NVFP4-MLA 同时压缩潜在缓存与注意力计算

用选择性四比特残差补偿敏感通道，以二维分块适配两次注意力矩阵乘，避免中途重新量化。MLA 即共享低维键值状态的多头潜在注意力。作者在 DeepSeek-R1 与 Kimi-K3 九项评测中保持接近 BF16 的平均准确率，缓存约缩小三倍；性能测量全部基于 Rubin。本周 TensorRT-LLM 主分支另将稠密路径扩到 SM100／103 的 Triton 后端，不能据此推断其他 GPU 的速度，或上期稀疏 DSA 缓存问题已全部解决。

[论文原文](https://arxiv.org/html/2611.18972v1) · [TensorRT-LLM 适配](https://github.com/NVIDIA/TensorRT-LLM/commit/268643600212c5de0f75122b94572f578bd050f8)

<a id="mistiq"></a>

#### MiSTiQ：极低位宽存储直接重建为微缩放格式

将格形编码与搜索结合，扩大缓存重建空间而不保存巨大码本，再通过 MX-Hash 直接生成目标低精度格式的重建值。作者在 Llama3、Qwen3 上研究约每元素 1.25 有效比特的键值缓存，报告优于所比基线的质量。值得关注的是压缩编码与计算格式的衔接；1.25 比特描述存储平均成本，不代表硬件原生执行该位宽，也不能由精度结果推出服务加速。

[原始资料](https://arxiv.org/abs/2611.21216)

<a id="qda"></a>

#### QDA：代理搜索可直接部署的量化配方

将多种训练后量化方法放进可组合库，由代理反复构建、评估配方。快速评价用模型输出分布差异筛选候选，再以长生成检查重复循环等失败，从而减少逐一完整评测的成本。研究覆盖四比特权重／十六或八比特激活以及三比特权重等配置，强调兼容既有服务内核。效果来自作者指定模型与任务，论文仍表述为将发布工具，不能写成成熟公开产品。

[原始资料](https://arxiv.org/abs/2611.23388)

<a id="draft-kv"></a>

#### 量化草稿缓存：位宽分配要与分组布局一起选

《Memory-Efficient Speculative Decoding with Quantized Draft KV Cache》只压缩投机解码草稿模型的缓存，目标模型和验证器保留 BF16。按通道分组量化键、按 token 量化值后，键一定比值更需要高精度的结论不再成立。作者在六组模型对上用 K4V4 降低草稿缓存占用，平均接受率仅小幅下降；总缓存节省小于草稿缓存节省，且接受率不是端到端速度。

[原始资料](https://arxiv.org/abs/2611.20565)

## 框架与工具升级

### vLLM

<a id="vllm-release"></a>

#### v0.34.0：低比特部署入口与启动缓存正式更新

正式版收录多种 FP8、MXFP8、NVFP4 与 AWQ／GPTQ 权重缓存重启路径，减少再次启动时重复处理权重的需要。升级时尤其要留意：Marlin W4A8 路径被移除，需改用 Humming 的输入量化配置；fp_quant checkpoint 也不再加载。此前报道的 Hadamard 旋转本期进入版本说明，不再重复介绍算法；正式版与后续主分支新增支持应分开看。

[原始资料](https://github.com/vllm-project/vllm/releases/tag/v0.34.0)

<a id="vllm-requant"></a>

#### 在线重新量化增加 block-FP8 到 MXFP4，并降低加载峰值

主分支扩展已量化专家权重的在线转换，支持带动态激活量化的 FP8 checkpoint，包括逐张量、逐通道及分块权重缩放。加载器先保留不占实际存储的参数描述，再逐层实例化、重新量化，减少源权重同时驻留的峰值。它扩大 checkpoint 到目标后端的转换路径；这是有损重新量化，目标格式仍受硬件限制，未提供通用精度或服务速度保证。

[原始资料](https://github.com/vllm-project/vllm/commit/fd2b7ac40fba94906ad44c84b6a51e77c9fae8a8)

### SGLang

<a id="ascend-hicache"></a>

#### 昇腾：FP8／MXFP8 缓存接入主机分层缓存

HiCache 是将设备缓存扩展到主机等层级的缓存系统。本次让 Ascend 950 上 ModelSlim 的 MLA FP8 与分组查询注意力 MXFP8 缓存可备份、恢复到本地主机内存，动态键缩放随页传输，静态值缩放保留在 NPU。MLA 的 BF16 旋转位置键仍独立保存。需显式启用昇腾传输后端，MXFP8 注意力依赖 CANN 9.2.0；这不是所有缓存分量都压成八比特。

[原始资料](https://github.com/sgl-project/sglang/commit/8c6ee5d5e6e37dfdc9af8558ffbb582ad4d9f7b4)

### Model Optimizer

<a id="modelopt-round"></a>

#### 重点推荐：修复 NVFP4 校准与导出在舍入边界不一致

此前动态 Triton 模拟量化与导出打包采用不同的缩放除法，在恰好位于四比特舍入边界时可能选中不同编码。修改统一为明确舍入的倒数乘法，并同步 Hugging Face、ONNX 打包与相关缩放搜索。新增边界测试直接覆盖校准值与导出权重的一致性。主分支已合入；保证范围限定所述动态 Triton 路径，不能扩大到所有后端或极小非正规缩放值。

[原始资料](https://github.com/NVIDIA/Model-Optimizer/commit/3c815f8db9717cb7f4cf44821e8e395edbb24c2b)
