## 论文与方法推荐

<a id="bitdecoding-fp4"></a>

### 重点推荐：BitDecoding-FP4 把误差控制与原生 FP4 解码一起设计

将查询拆成两个 FP4 张量表示残差，针对长上下文概率下溢调整缩放，并用平滑与正交旋转处理键的异常值。系统侧融合概率量化、重排 softmax 与分页缓存矩阵乘，让精度恢复机制进入原生 FP4 执行路径。论文同时研究 NVFP4 和 MXFP4，报告 B300 上的服务测量；这里推荐算法与内核协同思路，收益仍限于作者模型、负载与硬件，不能当作所有服务的通用倍数。

[论文原文](https://arxiv.org/abs/2611.09825)

<a id="foscar"></a>

### FOSCAR：减少 INT2／INT4 缓存的反量化指令

把逐缓存值的缩放与偏移运算折叠到注意力矩阵乘的另一个操作数或结果端，降低解码中的指令压力。它针对 H100、B200 分别设计流水线，并提供 SGLang 集成测量，说明压缩缓存后的解包成本也需要优化。这里的 INT2／INT4 是缓存表示，不意味着硬件直接执行两比特浮点乘法；论文的算子收益与服务收益应分别阅读。

[论文原文](https://arxiv.org/abs/2611.09722)

## 框架与工具升级

### vLLM

<a id="vllm-mxfp4-mla"></a>

#### ROCm 稀疏潜在注意力增加 MXFP4 缓存读写

新增 mxfp4_mla 缓存格式，将潜在键值按每 32 个数共享缩放的方式打包，覆盖写入、寻址与读取。对没有旋转位置编码分量的稀疏 MLA（多头潜在注意力）路径，数据读取后解包为 BF16 再进入现有矩阵乘；gfx950 使用硬件转换，其他支持路径用软件解包。测试覆盖 CDNA3／4，属于容量与搬运路径扩展，不能描述为原生 FP4 注意力。

[固定提交](https://github.com/vllm-project/vllm/commit/dac51063cc1295a2a8426998c4c372b19c42a0f9)

### SGLang

<a id="sglang-silu-nvfp4"></a>

#### 把激活函数与下一层 NVFP4 量化合并

将 SiLU 激活与门控相乘后直接生成下一线性层需要的 FP4 数据和缩放，减少中间张量及重复量化。下游线性层只有显式允许预量化输入时才跳过自身量化，避免普通元组误入该路径。该升级针对受支持的 NVIDIA NVFP4 稠密前馈网络，主分支包含单元测试；并非所有模型和后端都自动获得同样收益。

[固定提交](https://github.com/sgl-project/sglang/commit/ed037608a6843bd4b269ca0652540dbbc78c26a0)

### llama.cpp

<a id="llamacpp-fp8-kv-cuda"></a>

#### FP8 从基础格式扩展到缓存与 CUDA 执行

继此前基础格式支持后，本周新增带缩放的 FP8 键值缓存，并接入 CUDA 的转换、访存、矩阵向量乘与注意力路径。缓存缩放随模型加载和图执行传递，位置移动也考虑反量化；不同算子采用的实际计算精度仍有差别，例如部分矩阵向量乘采用八比特权重、十六比特激活。两项已合入主分支，但模型与后端支持有边界，不能把格式存在等同于全平台缓存可用。

[固定提交](https://github.com/ggml-org/llama.cpp/commit/202c1a229f5a83d1c9d758ed0f2d43760fa4bab0) · [固定提交 2](https://github.com/ggml-org/llama.cpp/commit/9e9619d030bbe6b584d826a0a6cf06e38251f52b)

### TensorRT-LLM

<a id="trt-cold-mixed"></a>

#### 冷缓存压缩保留首尾 token 的运行时精度

新增首 N 个与最近 N 个 token 的混合精度保留选项，仅压缩中间历史的冷页。冷页指移至主机或磁盘层的缓存页；GPU 内的历史仍保持运行时缓存类型，因此主要影响卸载容量与传输，并非把 GPU 注意力整体改为 FP4。该主分支功能按注意力层应用，滑动窗口层不参与，部分页组配置会被明确拒绝。

[固定提交](https://github.com/NVIDIA/TensorRT-LLM/commit/287f69ab6d591d6e7d11e0aadbd218c047007aaf)

<a id="trt-rc3-kv-correctness"></a>

#### v1.4.0rc3：NVFP4 缓存仍有模型正确性边界

本周候选版扩展若干低比特模型路径，同时明确列出：包括 GLM-5.2 在内的 DSA 稀疏注意力模型使用 NVFP4 缓存可能产生错误输出。这个限制会直接改变部署判断，不能只根据“支持 NVFP4”选择缓存类型。这里记录的是该候选版的已知问题，不宣称所有模型受影响，也不据后续主分支改动推断它已在该版本修复。

[发布说明](https://github.com/NVIDIA/TensorRT-LLM/releases/tag/v1.4.0rc3)

### AutoRound

<a id="autoround-rrq"></a>

#### 递归残差量化：同一 checkpoint 按需选择位宽

实验性接入递归残差量化（RRQ），把权重分成两比特基底与多个残差平面，加载时选择 2／4／6／8 比特或逐层混合精度。它使一个产物覆盖不同容量预算，无需每次重新量化；激活仍为十六比特。新增的是旧方法的工具集成，项目明确说明尚不支持生产级部署，也未证明所有服务后端都能直接消费该格式。

[固定提交](https://github.com/intel/auto-round/commit/b58069eab70c984bf1df2aaba730f29c1d0764ff)

### TorchAO

<a id="torchao-x86-lowbit"></a>

#### Arm 打包的低比特线性层现在可在 x86 执行

把原先会抛错的 x86 回退路径补成可执行实现，读取与 Arm 相同的低比特权重布局，并覆盖查表编码。八比特激活配 1—8 比特权重的导出模型因而能在 x86 评估，减少部署产物与开发环境之间的断层。它提供可移植整数运算与打包兼容性，不等于已经获得专门的 x86 向量化加速。

[固定提交](https://github.com/pytorch/ao/commit/82c6889c4a33041a7023467746b6a91da3e691d1)

### DeepSpeed

<a id="deepspeed-ascend-dequant"></a>

#### 昇腾 INT4／INT8 推理反量化恢复可用

修复昇腾 NPU 后端缺失的 INT4／INT8 到 FP16 反量化入口，按 DeepSpeed 的高半字节优先布局恢复权重。此前满足快速路径条件时会直接抛错；修复用普通 PyTorch 运算完成解包与缩放，不是新增原生低比特矩阵内核。INT4 的完整量化流程要求 CANN 9.0 及以上；作者报告在 910B4、CANN 9.0.1 上验证，本报未复跑。

[固定提交](https://github.com/deepspeedai/DeepSpeed/commit/f7a7177751cf6bdd54779fd9fe4390489258a563)
