# 低比特大模型推理周报
## 2026 年 10 月 2 日—10 月 9 日

**统计截至：2026 年 10 月 9 日 08:10（北京时间）**

本周的低比特推理进展比较密集。我认为最重要的变化集中在四个方向：

**第一，NVIDIA Blackwell 的 NVFP4 解量化开始真正使用 PTX ISA 9.4 的硬件指令。** FlashInfer 将 `QMUL4` 接入 B200/B300 的 NVFP4 sparse-MLA decode，消除了此前公开 PTX 实现与专用 kernel 之间约 5% 的性能差距。

**第二，NVFP4 精度优化继续向更复杂的 scale optimization 演进。** 新论文 OSFP4 不再独立优化 smoothing 或 block scale，而是联合优化两者；NVIDIA ModelOpt 则正式加入 MLA latent KV 的 NVFP4 伪量化配置。

**第三，KV Cache 量化开始向 1–2 bit 深入。** TaSQ 用 1-bit 向量量化压缩 KV；ResidualQuant 利用循环 Transformer 不同循环之间的 KV 相关性，把部分缓存压缩为 INT2 residual。

**第四，低比特推理的正确性问题仍然高度集中在数据生命周期。** 本周 SGLang 修复了一个 FP8 权重重载后 GSM8K 准确率从 45% 降至 1.5% 的问题；ModelOpt 则修复了 vLLM `torch.compile` 缓存导致伪量化可能根本没有执行的问题。

版本方面，**vLLM v0.31.0、SGLang v0.5.21** 已在本周发布。FlashInfer、TensorRT-LLM、ModelOpt 和 AITER 的重要增量主要集中在已合入 main 的 PR 中。

# A. 本周最重要的 10 项低比特进展

## 1. FlashInfer：B200/B300 的 NVFP4 Attention 开始真正使用硬件 QMUL4

**状态：[已合入 main]｜2026-10-08｜FlashInfer #6215**

[FlashInfer PR #6215](https://github.com/flashinfer-ai/flashinfer/pull/6215?utm_source=chatgpt.com)

这是我认为**本周最值得你关注的一项硬件软件协同优化**。

### 背景

FlashInfer 已有一套针对 DeepSeek-V4 NVFP4 sparse-MLA decode 的 CAKE kernel，能够直接消费 NVFP4 KV Cache。

在 decode 阶段，缓存中的每个 FP4 E2M1 数值需要乘以对应的 FP8 E4M3 block scale。

过去公开的 PTX 工具链缺少直接表达这一运算的指令，因此 FlashInfer 需要使用查表模拟。

而 CUDA 13.4 / PTX ISA 9.4 现在可以直接表达：

```ptx
mul.rn.e4m3x4.e2m1x4.e4m3x4.satfinite
```

该指令的作用是：

- 一次处理 4 个 E2M1 FP4 数值；
- 分别乘以对应的 E4M3 scale；
- 结果为 E4M3；
- 执行一次舍入并采用饱和有限值语义。

底层使用一条 **QMUL4 SASS 指令**，另外配合 `PRMT` 广播 scale bytes。

这意味着 NVFP4 解量化中的：

\[
x_{\mathrm{E4M3}}
=
\operatorname{Round}_{\mathrm{E4M3}}
\left(
x_{\mathrm{E2M1}}\times s_{\mathrm{E4M3}}
\right)
\]

可以直接由硬件执行，而不再依赖软件查表。

### 性能数据

作者使用 CUDA 13.4.92，在 B200/SM100 和 GB300/SM103 上分别测试 76 种 shape。

表中指标是 Cake source kernel latency / FlashInfer export kernel latency：

| GPU | 原查表实现 | 硬件 QMUL4 | 正确性 |
|---|---:|---:|---|
| B200 | 0.952× | **0.999×** | 76/76 bitwise 一致 |
| GB300 | 0.954× | **0.996×** | 76/76 bitwise 一致 |

原先 FlashInfer export 相对 Cake source 大约慢 5%，现在基本实现性能一致。

这并不是说整个 attention decode 加速了 5%，更准确的结论是：

> **使用硬件 QMUL4 消除了此前 NVFP4 解量化实现中的一部分软件模拟成本。**

### 一个重要的兼容性变化

该路径现在要求：

**CUDA Toolkit ≥ 13.4。**

低于 13.4 时不会静默使用慢速实现，而是明确报错。

目前仅影响 `backend="cake"` 的 SM100/SM103 NVFP4 decode；其他 BF16、SM120 路径不受影响。

**技术判断：** 这项工作比普通的 FP4 GEMM tuning 更重要，因为它表明 NVFP4 的 *scale multiplication* 已经成为具有专用硬件指令支持的操作。

这与你持续研究的 Rubin adaptive compression、scale block 与 Tensor Core 执行路径密切相关。不过，QMUL4 是一种 FP4×scale 转换指令，**不能仅凭它推断 Rubin 2:4 adaptive compression 的具体重打包机制**。

## 2. OSFP4：NVFP4 的 smoothing 和 block scale 开始联合优化

**状态：[论文]｜2026-10-06｜arXiv:2610.08231**

[OSFP4 论文](https://arxiv.org/abs/2610.08231?utm_source=chatgpt.com)  
[代码仓库](https://github.com/neriahbd/OSFP4?utm_source=chatgpt.com)

论文全名：

*OSFP4: Joint Optimization of Diagonal Smoothing and Block Scales for NVFP4 Quantization*

这篇是本周我最推荐深入阅读的 NVFP4 PTQ 论文。[arXiv](https://arxiv.org/abs/2610.08231?utm_source=chatgpt.com)

### 核心问题

过去很多 NVFP4 方法把两个步骤分开处理：

1. 对权重/激活进行 smoothing 或 rotation；
2. 再对变换后的数值选择 FP8 block scale。

例如：

`SmoothQuant-style transform`

→ `NVFP4 absmax/MSE scale`

或者：

`Hadamard rotation`

→ `NVFP4 scale search`

但这两个过程实际上是相互影响的。

改变 diagonal smoothing，会改变每个 16-value block 的数据分布；而 block scale 的离散可表示值，又决定 smoothing 是否真的降低最终 GEMM 输出误差。

因此 OSFP4 直接优化：

\[
\min_{D,S}
\left\|
XW-
Q_{\mathrm{NVFP4}}(XD^{-1};S_X)
Q_{\mathrm{NVFP4}}(DW;S_W)
\right\|_F^2
\]

这里的表达展示的是联合优化思想，而非论文完整的约束形式。

作者同时考虑两种实际量化过程：

- Round-to-Nearest；
- GPTQ 风格的 Successive Interference Cancellation。

优化中还引入 multiplicative-dither FP4 surrogate，使离散量化带来的优化困难更容易处理。

### 与 H-Scale、4over6 有什么区别？

| 方法 | 主要优化变量 | 运行时额外成本 |
|---|---|---|
| RTN / Absmax | 基础 block scale | 无 |
| Four-Over-Six | block scale 的离散范围选择 | 无 |
| H-Scale | activation/Hessian-aware local scale | 无 |
| **OSFP4** | **Diagonal smoothing + local block scale** | 取决于变换能否完全折叠 |

论文强调尽量保持 NVFP4 原生硬件路径。

作者报告其方法在测试的量化设置下取得比较方法中最高的平均准确率，同时保留供应商 NVFP4 prefill throughput 的 **94%–97%**。

这个数字说明它并非绝对零性能代价。

### 我的判断

最近几周的低比特 PTQ 工作正在形成一个清晰趋势：

**FP4 value code 不变，优化空间继续向 block scale、smoothing、rotation 和误差传播扩展。**

对于你研究的 NVFP4，与其继续只比较不同 FP4 codebook，不如重点分析：

- FP8 local scale 的离散搜索空间；
- global scale 与 local scale 的相互影响；
- scale search 是否考虑真实 activation covariance；
- smoothing 是否改变 Tensor Core 所需的输入 layout；
- 变换能否折叠到已有权重中。

## 3. ModelOpt：正式加入 MLA latent KV Cache 的 NVFP4 伪量化

**状态：[已合入 main]｜2026-10-03｜ModelOpt #2620**

[ModelOpt PR #2620](https://github.com/NVIDIA/Model-Optimizer/pull/2620?utm_source=chatgpt.com)

这项与你当前 GLM-5.x-NVFP4 的 KV Cache 实验直接相关。

### 新增的量化对象

ModelOpt 新增：

`configs/ptq/units/kv_nvfp4_mla`

专门处理 MLA 中的：

`kv_c_bmm_quantizer`

也就是缓存中的 compressed latent KV。

对应流程可以理解为：

```text
MLA compressed KV latent
       ↓
NVFP4 fake quantization
       ↓
参与后续 attention 计算
```

而不是传统 MHA/GQA 的：

`k_bmm_quantizer / v_bmm_quantizer`

因为 MLA 的 KV Cache 本来就是低维 latent representation，不能机械套用普通 K/V 两路量化配置。

### RoPE K 的处理

PR 的后续修订还明确区分了两部分：

**Compressed latent KV：NVFP4**

**RoPE positional K：FP8 或模型对应的高精度表示**

对于 DeepSeek-V3 一类同时包含 latent KV 和 `k_pe` 的 MLA，不能简单把整个 K Cache 按同一种 NVFP4 规则处理。

对 NoPE 结构则需要根据模型本身确认 RoPE 通道是否存在。

### 重要限制

当前 PR 是 **fake quantization / PTQ serving simulation**，并不等于已经增加了新的 NVFP4 attention compute kernel。

此外，示例设置的 tensor global scale 为 1。

因此它能用于评估量化影响，但如果要模拟真实 NVFP4 硬件数值语义，还需要继续检查：

- E2M1 rounding；
- FP8 block-scale rounding；
- global scale；
- saturate/clamp；
- 特殊值；
- prefill/decode 两条路径。

特别值得注意的是，同一周 ModelOpt 还修复了 vLLM fake-quant serving 的多个缺陷，下面会单独讨论。

## 4. FlashInfer：Rubin Frost MoE 进一步进入可调度 backend 体系

**状态：[已合入 main]｜2026-10-06｜FlashInfer #6035**

[FlashInfer PR #6035](https://github.com/flashinfer-ai/flashinfer/pull/6035?utm_source=chatgpt.com)

上周已经出现 Rubin SM107 上的 cuDNN Frost-generated MoE。

本周 #6035 进一步调整 Frost 的集成位置，使它能够更系统地参与 FlashInfer 的 backend selection 和 autotuning。

这次比较方式比较严谨：同一份代码、相同 workload，分别对“原 backend pool”和“增加 Frost 后的 backend pool”独立 autotune。

### Rubin SM107 实测

576 个测试配置，涵盖：

- 8 组模型 MoE geometry；
- 4 种 precision 组合；
- 9 个 token count；
- uniform/skew routing。

测试采用 warm CUDA Graph replay、EP=1。

结果：

| Precision | 全部配置几何平均 | T≥4096 |
|---|---:|---:|
| BF16 | 1.002× | — |
| **MXFP8** | **1.155×** | **1.464×** |
| NVFP4 | 1.008× | — |
| **MXFP4 W × MXFP8 A** | **1.052×** | **1.125×** |

最大收益来自 MXFP8：

DeepSeek-V2-Lite、T=16384 时：

**1060.78 μs → 596.13 μs，1.779×。**

不过必须注意：

**这不是整模型推理加速。**

数据对应单层 MoE kernel latency，且不包括输入量化、权重准备以及 autotuning。

### 技术结论

Frost 的优势非常依赖：

`dtype × MoE geometry × token count × routing distribution`

特别值得注意的是：

**MXFP8 收益明显，而 NVFP4 平均收益很小。**

这意味着 Rubin 上的低比特 MoE 不应该假设“新生成式 kernel 对所有 datatype 都有显著收益”。

实际需要让 autotuner 在 Frost、CuTe DSL、TRT-LLM 等 backend 之间选择。

## 5. FlashInfer：Rubin Expert Parallel 开始支持 NVFP4/MXFP8 quantized combine

**状态：[已合入 main]｜2026-10-04｜FlashInfer #5991**

[FlashInfer PR #5991](https://github.com/flashinfer-ai/flashinfer/pull/5991?utm_source=chatgpt.com)

这项工作进一步把低比特延伸到 Expert Parallel 的 combine 阶段。

此前我们已经看到：

`MXFP8 dispatch → Expert Parallel → W4A8 MoE`

本周 Rubin SM107 的 MegaMoE backend 开始提供：

**NVFP4 或 MXFP8 格式的 FC2 return/combine payload。**

最终输出仍保持 BF16。

### 新增两类配置

**GenPhase kernel**

当前限制每 rank 最多 1024 tokens，combine 为 BF16。

**Quantized combine**

允许 FC2 输出使用 NVFP4 或 MXFP8 作为中间格式，之后执行独立的 top-k reduction。

这使低比特覆盖的数据流进一步扩大：

```text
Activation
   ↓
Quantization
   ↓
EP Dispatch
   ↓
MoE FC1 / FC2
   ↓
Quantized Return Payload
   ↓
Combine / Top-K Reduction
   ↓
BF16 Output
```

目前默认仍然使用标准 BF16 combine，新增路径属于显式配置能力。

**工程意义：** 未来大型 MoE 的通信优化不会只发生在 dispatch 方向，也会发生在 combine 方向。

不过本 PR 没有给出足以证明 quantized combine 端到端收益的完整 serving benchmark，因此我暂时不对性能做定量结论。

## 6. TaSQ：1-bit KV Cache 量化不再只依赖通用 VQ codebook

**状态：[论文]｜2026-10-02｜arXiv:2610.03027**

[TaSQ 论文](https://arxiv.org/abs/2610.03027?utm_source=chatgpt.com)

论文全名：

*Tailoring the Quantization Space for 1-Bit KV Cache Compression*

过去的向量量化通常直接在 K/V activation 空间中学习 codebook。

当每个数值的平均存储预算降低到 1 bit 左右时，codebook 容量有限，很容易出现显著的 attention error。

TaSQ 的核心思路是：

**先改变 VQ 所面对的数值空间，再进行极低比特编码。**

主要包含三个组成部分：

1. Query-guided channel weighting；
2. Cross-head normalization；
3. Covariance-aware channel grouping。

最重要的是作者强调这些变换与 RoPE 兼容，且可以合并进 projection weight 或 codebook，因此不需要为每次 attention 新增复杂的变换计算。

### 实验结果

单张 RTX 6000 Ada GPU、SGLang 实现：

- 最大可支持 batch size 提升 **14×**；
- peak throughput 提升 **1.87×**；
- 对比基线为 BF16 KV Cache。

论文还覆盖长 CoT reasoning 与长上下文检索。[arXiv](https://arxiv.org/abs/2610.03027?utm_source=chatgpt.com)

### 与 NVFP4 KV 有什么区别？

NVFP4：

`4-bit E2M1 value + block scale`

TaSQ：

`VQ code + codebook + 变换后的向量空间`

因此 TaSQ 的 1-bit 并不意味着 GPU 可以直接使用原生 1-bit Tensor Core attention。

它属于 **compression-oriented KV representation**。

未来如果要在 B200 上获得速度收益，仍然必须解决：

- codebook lookup；
- 解码成本；
- KV page layout；
- attention consumer；
- decode bandwidth。

尤其需要注意论文的 14× batch capacity 并不等于 14× throughput。

## 7. ResidualQuant：利用循环 Transformer 的跨循环相关性，把 KV 压到 INT2 residual

**状态：[论文]｜2026-10-07｜arXiv:2610.10381**

[ResidualQuant 论文](https://arxiv.org/abs/2610.10381?utm_source=chatgpt.com)

这篇论文提出了一个很值得关注的思路：

> 如果模型不同层或不同阶段保存的数据高度相似，就不一定要独立量化所有 KV。

论文研究的是 Looped Transformer。

这类模型反复使用共享 Transformer block，从而增加有效网络深度。

虽然参数被复用，但每轮循环仍可能产生不同的 KV state。

作者发现，不同 loop 的 KV state 高度相关，因此采用：

**最后一次 loop 的 KV 作为 reference。**

之前各轮则保存：

`KV(loop_i) − KV(reference)`

的低精度 residual。

进一步结合：

- INT2 residual quantization；
- Least-squares scale；
- Residual rotation；
- Loop-wise mixed precision。

### 结果

论文报告：

- 理论 KV memory 减少 **80.7%**；
- 相同 memory budget 下，准确率最高比 rotation baseline 高 **13 个百分点**；
- RTX 5090 fixed-batch decode 最高 **2.73×**；
- batch capacity 提高后，peak throughput 最高 **4.15×**。[arXiv](https://arxiv.org/abs/2610.10381)

### 我的判断

这是一个非常有价值但适用范围明确的方向。

它依赖 Looped Transformer 的跨循环相关性，并不能直接套用普通 Transformer。

但它提供了一个可以继续研究的思想：

**低比特压缩不一定只考虑单个 tensor 内部的分布，也可以利用不同 KV state 之间的相关性。**

如果某些模型存在跨层共享 KV、重复 latent 或相似 indexer state，类似 residual-based compression 可能值得探索。

## 8. vLLM：GLM-5.3 默认采用 FP8 KV，吞吐提升 2.3%–5.5%，但 TTFT 反而退化

**状态：[已合入 main]｜2026-10-06｜vLLM #60140**

[vLLM PR #60140](https://github.com/vllm-project/vllm/pull/60140?utm_source=chatgpt.com)

这项与你目前 GLM 系列模型的低比特 KV 实验很相关。

vLLM 修改 GLM-5.3 的默认 KV cache precision，优先使用 FP8。

### 显存变化

在作者给出的 458,880-token KV budget 下，每 rank：

**40.13 GiB → 20.69 GiB。**

接近减半。

### 性能数据

| Concurrency | 原吞吐 tok/s | FP8 KV tok/s | 提升 |
|---|---:|---:|---:|
| 1 | 178.5 | 186.1 | +4.2% |
| 4 | 328.3 | 346.4 | **+5.5%** |
| 16 | 631.8 | 646.5 | +2.3% |

但 TTFT：

- C1：+11.1%；
- C4：+10.1%；
- C16：+6.9%。

换言之：

**吞吐改善，但首 token 延迟变差。**

GSM8K flexible-extract：

- 原实现 0.9189；
- FP8 KV 0.9212。

没有观察到明显任务精度退化。

### 技术意义

这个结果说明：

**KV 量化不是只看 decode latency。**

FP8 KV 减少了存储和读取的数据量，但前面的 quantization、scale generation、prefill 写入路径可能增加 TTFT。

尤其对你后续研究 GLM-5.2-NVFP4 的 Q/K 伪量化，建议把：

`Prefill KV quant cost`

和

`Decode KV bandwidth saving`

分开测量，而不是直接根据一个 E2E tok/s 判断低比特是否值得。

## 9. SGLang：FP8 权重重载发生严重 silent accuracy regression

**状态：[已合入 main]｜2026-10-07｜SGLang #42585**

[SGLang PR #42585](https://github.com/sgl-project/sglang/pull/42585?utm_source=chatgpt.com)

这是本周我认为**最危险的低比特正确性案例**。

### 问题

SGLang 支持在线 FP8 量化与模型权重 reload。

此前部分路径在模型重新加载权重时：

`BF16 checkpoint`

→ `先 FP8 quant`

→ `再做 TP sharding`

但在更新 per-channel scale 时使用了错误的分区。

因此同一份 checkpoint：

**第一次启动正常，reload 后精度严重下降。**

Qwen3-0.6B、TP4/Attention-DP2，GSM8K 200 题子集：

**45% → 1.5%。**

并且模型不一定 crash。

### 修复

将过程调整为：

`BF16 checkpoint`

→ `根据实际 TP rank 完成 native sharding`

→ `在本地 shard 上重新 FP8 quant`

这样 scale 所对应的 weight partition 与实际执行时完全一致。

修复后完整 311 个 weight keys、29 个 chunk 的 reload 测试：

- 200 条生成输出一致；
- 21,082 个 generated-token logprobs 一致；
- 3,995 个 teacher-forced gold-token logprobs 一致。

同时额外分配的峰值内存：

**350.71 MiB → 16.63 MiB。**

### 为什么重要？

如果你未来做低比特强化学习或持续权重更新，这类问题非常容易隐藏。

原因是：

**首次启动的 accuracy test 并不能覆盖 repeated reload 后的量化 scale correctness。**

以后 FP8/NVFP4 online quantization 最好固定做：

`cold load`

→ `reload unchanged weights`

→ `compare logits bitwise`

→ `repeat reload N times`

而不能只做一轮下游任务。

## 10. ModelOpt：修复 vLLM fake quant 可能根本没有执行的问题

**状态：[已合入 main]｜2026-10-02｜ModelOpt #2633**

[ModelOpt PR #2633](https://github.com/NVIDIA/Model-Optimizer/pull/2633?utm_source=chatgpt.com)

这项与你当前的量化实验方法有直接关系。

PR 修复了几个问题：

**第一，pre-quantized checkpoint 与 fake quant 的兼容性。**

例如 checkpoint 本来已经是 FP8，之前可能触发 assertion。

现在可以让这些已量化层直接通过，但不允许在相同模块上重复设置冲突的 fake-quant 配置。

**第二，KV cache dtype 与 attention activation dtype 混淆。**

例如：

`--kv-cache-dtype fp8`

之前 ModelOpt 可能把这个参数错误理解为 attention layer 的数值精度。

**第三，MLA 的 KV quant config 可能静默失效。**

vLLM 0.16 之后 attention layer 的导入位置已经变化，旧代码使用的类型判断不再成立。

因此：

`KV_QUANT_CFG`

可能设置了，却没有真正进入 MLA 量化流程。

**第四，CUDA Graph 与 constant-amax fake quant 不兼容。**

部分 quantizer 每次执行时都从 host 复制 amax，影响 CUDA Graph capture。

**第五，也是我认为最重要的：torch.compile 缓存可能让 fake quant 被完全跳过。**

vLLM 复用了没有 fake quant 的旧编译图，导致你以为已经打开了量化，实际上走的还是原始路径。

修复后的 launcher 默认：

`VLLM_DISABLE_COMPILE_CACHE=1`

以避免复用错误图。

作者使用 B200、vLLM 0.30、GLM-5.3-Flash、DeepSeek-V3 等模型验证。

### 对你的直接启示

如果你用 vLLM 研究：

`BF16 Q → MXFP8 fake Q`

或者：

`MLA latent KV → NVFP4 fake quant`

不能只看最后 accuracy 有没有下降。

还应该抓取实际量化前后的 tensor，验证：

- fake quant 真的执行；
- prefill 和 decode 都执行；
- 输出出现符合目标量化格式的离散值；
- eager 与 CUDA Graph 数值符合预期；
- 编译缓存没有替换掉自定义 kernel。

这类检查对得出可信的低比特 accuracy 结论非常重要。

## SoloQ：Diffusion LLM 的无校准 NVFP4 量化

**论文：SoloQ: Calibration-Free Quantization for Diffusion Language Models**

[SoloQ 原文](https://arxiv.org/abs/2610.07121?utm_source=chatgpt.com)

Diffusion LLM 与自回归模型不同。

它可能在不同 denoising step、不同 mask pattern 下产生明显变化的 activation distribution。

传统 PTQ 往往需要大量 calibration sample，而且 calibration 数据是否覆盖真实 inference 状态本身就是问题。

SoloQ 使用：

`K-RPBH structured rotation`

+

`lightweight rescaling`

使旋转后的数值分布更容易预测，从而减少对真实 calibration data 的依赖。

它同时兼容 distribution-matched codebook 与 native NVFP4。

在 block-diffusion 模型上，作者还引入：

**commit-time KV cache quantization**

即只在一个 block 完成生成、状态被正式提交后再量化对应的持久化 KV，避免在正在 denoise 的 active block 上反复引入量化扰动。

在 LLaDA、Dream、Fast-dLLM v2 和 Nemotron-Labs-Diffusion 等模型上：

- peak memory 最高减少 **2.61×**；
- end-to-end inference 最高加速 **2.24×**。[arXiv](https://arxiv.org/abs/2610.07121?utm_source=chatgpt.com)

这项工作说明，低比特量化策略应该考虑模型的生成机制。

自回归模型通常是：

`token commit → KV append`

而 diffusion model 可能是：

`多次更新同一批 token → block commit`

因此 KV 应该在哪个时刻量化，本身就会影响准确率。

```text
Scale / metadata decode
        ↓
Low-bit conversion
        ↓
MMA operand preparation
        ↓
MMA execution
        ↓
Quantized EP return
        ↓
Combine
```

我认为这会比只跟踪 Rubin 峰值 FP4 TFLOPS 更有价值。

尤其值得观察：

**Rubin 的 adaptive compression 是否能减少上述数据流中的 scale decode、metadata movement、operand preparation 成本。**

目前这一点仍属于值得验证的推测，不能直接从公开软件 PR 得出硬件已实现的结论。

# 本周最重要的三个趋势判断

### 第一，NVFP4 的精度研究正从固定量化规则转向联合优化。

OSFP4 联合 smoothing 与 block scale，ModelOpt 增加 scale learning，说明在原生 E2M1 数值格式不变的情况下，仍然有大量精度优化空间。

未来更值得关注的可能不是“新的 FP4”，而是：

**怎样让同一个 NVFP4 硬件格式表达更多有效信息。**

### 第二，低比特 KV Cache 正继续向极端压缩与结构化压缩演进。

TaSQ 的 1-bit VQ、ResidualQuant 的 INT2 residual，以及 ModelOpt 的 NVFP4 MLA latent quantization，分别代表：

**向量编码、跨状态相关性、硬件原生 block scaling**

三条不同路线。

它们并不互相替代，也不能单纯按 bit 数比较优劣。

真正需要比较的是：

`bytes/token × dequant cost × attention accuracy × native kernel support`

### 第三，低比特系统最大的风险仍然是 producer/consumer numerics 不一致。

本周三个代表性例子：

- SGLang：FP8 reload 的 sharding/scale 顺序错误；
- ModelOpt：compile cache 可能让 fake quant 静默失效；
- FlashInfer：QMUL4 才让公开 JIT 的 NVFP4 dequant 达到专用 source kernel 的性能。

它们说明低比特不仅是一种数值格式，更是一套贯穿：

**训练 → checkpoint → loader → quantizer → cache → kernel → communication**

的执行契约。
