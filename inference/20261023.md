<a id="sglang-nvfp4-clamp"></a>
## gate/up 不同 scale 会改变 clamp 含义｜SGLANG-NVFP4-CLAMP｜已合入主分支｜10-22 UTC｜ModelOpt NVFP4 / TRT-LLM MoE 后端

**结论：** SGLang 在加载阶段统一 gate/up 的有效 alpha，修复共享 raw clamp 被解释为不同反量化阈值的问题；原来的精度警告不能保证语义正确。

**技术机制与证据：** 后端对两半原始 GEMM1 输出施加同一 clamp。若以 gate alpha 把真实阈值 L 换算为 raw 阈值，而 up alpha 不同，那么 up 实际阈值为 `L × alpha_up / alpha_gate`。比例为四时，配置七实际对应二十八；激活函数参数相同并不能消除偏差。

新代码取 `shared_alpha = max(alpha_gate, alpha_up)`，把较小 alpha 的比例折入 E4M3 block scales，再以共同 alpha 计算 clamp 等后续参数。物理布局明确为 `[up, gate]`，可能与变量名的直觉顺序相反。数据流是“加载 packed 权重和两级 scale → 重标定 block scale → GEMM1 → shared clamp → 激活/第二 GEMM”。修改在 load 阶段完成，没有新增 forward 操作。[固定实现与 diff](https://github.com/sgl-project/sglang/commit/9301ca37a0173fe6b5d5d53ef7ed40b76adf33e3)。

**边界与影响：** 合入的 CPU 单测检查两半有效阈值、scale/权重乘积和 SiTU 的不同处理，GPU packing 被 mock。真实 E4M3 scale 重新存储有舍入边界，理想实数下乘积不变不等于全部 checkpoint 误差不变。核验日 PR 描述提及早期 GB300 开发测试，但注明最终 rebase 后未重跑、临时 GPU fixture 未纳入提交；本期不将其写成最终 revision 的完整硬件验证或模型精度保证。[验证说明](https://github.com/sgl-project/sglang/pull/45386)。

适用范围是带 clamp 且 gate/up global scales 不同的 MoE checkpoint，不应泛化到所有 NVFP4 推理。检查须记录 scale 比例、实际后端与激活配置，比较反量化域输出。加载成功、无 NaN 或短文本可读，都不能证明阈值语义正确；来源也不支持将修复转换为 TTFT 或吞吐提升数字。

<a id="aiter-packed-kv-span"></a>
## packed KV 元素数不等于寻址跨度｜AITER-PACKED-KV-SPAN｜已合入主分支｜10-22 UTC｜gfx950 Gluon

AITER 用 `nelement × element_size` 判断 32-bit buffer offset 是否足够；交错 K/V 的每个 strided view 只有半数元素，却可跨整个 cache，2–4 GiB 区间会误选路径。修复改用 K/V 最大可寻址字节跨度。新增测试用 40,000 blocks、BF16 packed cache 访问超过 2 GiB 的尾部，对照连续布局 reference。这是地址正确性修复，不是 FP8 精度恢复，也不证明其他 attention 后端均受影响。[实现与测试](https://github.com/ROCm/aiter/commit/272586aa0901d9b558af3298109d9e77f54b50f2)。

<a id="modelopt-native-fp8-ptq"></a>
## 原生 FP8 再量化前须消费原 scale｜MODELOPT-NATIVE-FP8-PTQ｜已合入主分支｜10-16 UTC

ModelOpt 修复 Transformers FP8Experts 校准/导出：原生 FP8 payload 不能直接当真实权重求 amax 或打包 NVFP4。新路径逐 expert projection 反量化，scale 乘法保留 FP32 到输出 cast，导出移除已消费 scale；fold 前显式 unpack。测试独立解码 packed NVFP4，以原 payload 乘原 scale 为参考。受影响导出应回原 checkpoint 重生成，不能只重命名 dtype。[固定实现与测试](https://github.com/NVIDIA/Model-Optimizer/commit/264fd262e0ce9667c934d7c30c75c2b5f32b2f7c)。

<a id="fa-unused-v-tail"></a>
## Mask 掉概率仍挡不住 V 尾部 NaN｜FA-UNUSED-V-TAIL｜已合入主分支｜10-21 UTC｜CuTe / SM100

FlashAttention 修复 nonpaged V 的 TMA 读取：P 已置零仍会在 PV 遇到 `0 × NaN`，污染输出。新 descriptor 按每条序列实际长度越界零填充，并保留真实 feature 边界和 64-bit 地址计算；不是简单清空整个 cache。回归覆盖 dense/packed、GQA、SplitKV、stride，并检查有效区 NaN 仍传播。范围是该非分页加载路径，不代表全部 KV 后端都已修复。[固定实现与测试](https://github.com/Dao-AILab/flash-attention/commit/a6fcdfdba17bf5c643d9d2efa275222677399787)。
