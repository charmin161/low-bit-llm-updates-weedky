## 论文与方法推荐

<a id="loopvq"></a>

#### 重点推荐：LoopVQ 利用循环维冗余压缩 KV 缓存

LoopVQ 把循环 Transformer 多次循环的键值缓存联合编码，让一个码本索引服务多个循环步骤，并按输出误差优化码本。论文在 Ouro、Huginn 上研究平均每元素 0.5／0.25 比特的表示，并实现 SGLang 原型；这是码本压缩，不是硬件直接计算零点几比特浮点。效率主要在 RTX 6000 Ada 上与 BF16 服务比较，预填充编码会增加开销，且部分近期 token 仍保留 BF16。

[论文原文](https://arxiv.org/html/2611.05304v1)

<a id="agent-quality"></a>

#### Beyond Accuracy：量化后的编程代理行为也要看

研究比较 Qwen2.5-Coder 与 Devstral 的 BF16、四比特 AWQ／GPTQ，在 OJBench 上观察多轮编程与工具调用。作者未检测到显著的最终准确率下降，但一次解题成功与依赖反复执行纠错的比例会变化。它提醒读者，单一正确率不足以评估量化代理的交互成本；结论限定于这些模型、任务和三个随机种子，不代表所有代理无精度损失。

[论文原文](https://arxiv.org/abs/2611.02368v1)

## 框架与工具升级

### vLLM

<a id="vllm-cache"></a>

#### Kimi K3.1 Pro：低比特潜在缓存与索引缓存协同

官方新博客说明，注意力的潜在键值缓存可选 NVFP4，稀疏索引键可独立选 MXFP4，压缩布局可用于预填充与解码分离传输。值得关注的是，容量优化覆盖两类缓存，而不只压缩模型权重；上下文并行还可按 token 分摊缓存。不同配置分别适用于文中列出的 NVIDIA 与 AMD 后端，不能把一种组合的收益套给全部设备。本文是新支持与机制介绍，完整服务收益仍依赖上下文、并发及通信开销。

[官方技术介绍](https://vllm.ai/blog/2026-11-04-kimi-k31-pro)

<a id="vllm-rotation"></a>

#### MXFP4 输入旋转与 Quark 导出模型接通

主分支合入按块 Hadamard 正交旋转的线性层包装器，支持在线 MXFP4 量化及已带旋转信息的 Quark checkpoint。权重和输入采用配套变换，将异常值分散到块内，减少低比特量化误差。实现核查旋转矩阵并避免重复旋转权重，测试覆盖实际 AITER 与模拟路径；这是需要选择的线性层路径，不能把同周尚在草案中的 MoE 扩展算作已完成。

[实现与验证](https://github.com/vllm-project/vllm/pull/62750)

### SGLang

<a id="sglang-engram"></a>

#### Engram 查表保留 MXFP4 打包，减少主机内存

DeepSeek-V4.1 的 Engram 表加载后保持四比特打包，查表时再解码，避免提前扩成 FP8。作者在 GB300、四路张量并行且表驻留 CPU 的配置中，将整节点两张表的主机内存从约 189 GiB 降至 97 GiB；该配置的 GPU 显存没有下降。测试覆盖全部字节编码和负零，并与扩宽后的查表结果逐位比较。主分支已合入，小批量主机查表可能略慢，不能写成全面提速。

[实现与验证](https://github.com/sgl-project/sglang/pull/47935)

### llama.cpp

<a id="llamacpp-release"></a>

#### v0.9.0：OCP FP8 E4M3 进入正式版本

上期跟踪的 OCP FP8 E4M3 基础格式本周进入 v0.9.0 正式发布，并随 ggml v0.29.0 提供相应格式支持。新增证据是发布状态变化，格式本身不是本周首次提出。八比特浮点的文件表示、转换能力与各后端原生执行是不同层次；发布说明不足以证明每个平台都获得端到端加速。对需要稳定版本入口的读者，这比追逐单个主分支提交更方便。

[正式发布说明](https://github.com/ggml-org/llama.cpp/releases/tag/v0.9.0)

### AutoRound

<a id="autoround"></a>

#### 张量并行与低秩适配扩展量化调优路径

主分支加入张量并行配置与 LoRA 低秩参数支持，并调整 FP4 混合专家模型的调优实现。值得关注的是，量化工具开始同时处理多设备分摊和低秩优化参数，以扩大可调优模型范围。实现包含低秩缩放、参数校验等测试；这是涉及较多重构的合入，不等于已随稳定版发布，也没有足够统一条件支持通用加速倍数。

[固定提交与源码](https://github.com/intel/auto-round/commit/5db1082901dfba6e710f46e11bcc00cad30a5af3)
