## Rubin Adaptive Compression：本次有实质性新进展

相较于此前主要依赖 **Rubin 架构博客 + PTX 9.4 指令语义**来反推实现路线，这一轮最重要的变化是：**Rubin 已开始进入 CUDA、Transformer Engine、CUTLASS 和 cuBLAS 的正式软件栈**。这使得此前若干 ISA 层面的推断明显更“落地”，但 NVIDIA 仍然没有公开一个名为 `adaptive_compression` 的 TE API 或完整端到端示例。

### 发生了什么变化

**已确认事实：2026 年 9 月 9 日 CUDA 13.4 GA 把 Rubin 从“ISA 已披露”推进到了可编译、可链接、可由库分发 kernel 的开发者预览状态。** CUDA 13.4.1 正式支持 PTX ISA 9.4，并将 Vera Rubin / Compute Capability 10.7 纳入 Developer Preview；Rubin 新功能要求 R615 驱动。更关键的是，cuBLAS 13.4 已明确写入 Rubin 10.7 支持，而且 release notes 甚至列出了 **Rubin 上 NVFP4 `cublasLtMatmul()` 特定 algorithm/stage 组合会产生错误结果**的已知问题。这意味着 NVIDIA 内部已经存在实际的 Rubin NVFP4 kernel/algorithm dispatch，而不只是文档预留。([NVIDIA Docs][1])

**Transformer Engine 2.19 出现了一个非常直接的新信号：`Added Rubin SM107a support when building with CUDA 13.4 or later`。** 这是目前我认为与 TE3 最相关的新变化。TE 已经知道 `SM107a`，而不是仅仅依赖通用 PTX forward compatibility。但值得注意的是，TE 2.19 当前公开的 recipe 仍然是 NVFP4、MXFP8、hybrid quantization、2D block scaling 等；release notes **没有出现公开的 Adaptive Compression recipe、开关或 API**。([NVIDIA Docs][2])

同时，**2026 年 8 月 25 日的 CUTLASS 4.8** 已首次公开 Rubin kernel building blocks，包括 Rubin FP8/FP4 Tensor Core、**B collector reuse**、576-column TMEM、328 KB shared memory 和 Rubin block-scaled GEMM。CUTLASS 文档同样明确要求 R615 才能执行 Rubin kernel。这个变化很重要，因为此前 PTX 中的 `.collector::b::*` 更像 ISA 线索，现在已经进入 NVIDIA 公共 kernel abstraction。([NVIDIA Docs][3])

### 证据可靠性与来源等级

这次核心结论全部来自 **NVIDIA 一级官方资料**：CUDA 13.4 Release Notes、Transformer Engine 2.19 Release Notes、CUTLASS 4.8 changelog，以及当前 PTX ISA 9.4 文档。因此我没有采用论坛传闻或低置信度第三方反汇编。

PTX 9.4 当前文档仍明确列出 Rubin 的 `spcompress / spdecompress`、`tcgen05.mma.sp`、`tcgen05.mma.ws.sp`、Zero-Column Mask Descriptor，以及新的 Rubin 数据路径布局；`spcompress` 仍然是非常明确的 **2:4 structured sparsity compression primitive**。([NVIDIA Docs][4])

这里需要特别区分三种证据等级：

**已确认事实**：Rubin SM107a、2:4 `spcompress`、sparse MMA、zero-column mask、B collector、LUT/decompression 等硬件/ISA primitive 存在；CUDA/TE/CUTLASS 已开始真正支持 Rubin。

**强证据推断**：这些 primitive 中，`spcompress → metadata → sparse MMA` 很可能就是 TE3 Adaptive Compression 的核心执行路径之一。

**仍未证实**：NVIDIA 尚未明确说“TE3 Adaptive Compression = `spcompress`”，也没有公开证明 Adaptive Compression 只由这一条路径构成。

### 对可能技术路线的含义

现在我会把 Rubin 的“compression”明确拆成至少 **两条不同的硬件路线**，而不再把所有线索归为一种压缩。

第一条是我认为与 **Adaptive Compression 本体关联最强**的路线：

`dense activation / TMEM`
→ `tcgen05.ld{.red}.spcompress`
→ 每 4 个值按 MAX / MAXABS / MIN / MINABS 动态保留 2 个
→ 同时生成 sparsity metadata
→ `tcgen05.mma.sp` / `tcgen05.mma.ws.sp`
→ Tensor Core sparse MMA。

它最关键的意义并不是“Rubin 支持 2:4”——以前 NVIDIA GPU 就有结构化 sparsity——而是 **Rubin 可以在数据进入 Tensor Core 数据路径时动态完成 selection + compression + metadata generation**。这非常适合 activation，因为 activation 无法像 weight 一样离线预压缩。如果最终 TE3 Adaptive Compression 面向 attention/MLP activation 做动态稀疏，我目前认为这是最自然的硬件实现。PTX 9.4 中 sparse A 的 metadata layout 和 dedicated sparse data-path 也与这一解释高度一致。([NVIDIA Docs][5])

第二条则是 **B/weight 表示压缩路线**：

`compressed B`
→ 低比特索引 / LUT representation
→ Tensor Core 内部 inline reconstruction
→ B collector 缓存并跨 MMA 重用
→ GEMM。

它更像“减少 B 侧搬运和重复读取”的 representation compression。CUTLASS 4.8 现在正式暴露 **B collector reuse**，明显提高了这条路线的可信度。但我不建议再把它与 2:4 adaptive activation sparsification 混为一谈。([NVIDIA Docs][3])

而 **Zero-Column Mask Descriptor** 我仍然倾向于看成第三种、互补的 gating/skip 机制。它的 descriptor 是 start/span/skip/use 这类有明显结构约束的描述方式，而不是任意 2:4 metadata bitmap，因此目前没有证据说明它就是 `spcompress` 的 metadata。更合理的解释仍然是：它用于让 MMA 直接忽略某些 B columns/span，例如 attention 或其他具有列级/块级结构的稀疏模式。([NVIDIA Docs][4])

### 与此前判断相比是否需要修正

**需要小幅修正，但不是推翻。**

此前“Rubin Adaptive Compression 很可能涉及动态 activation 2:4 + sparse MMA”的判断，我现在会**提高置信度**。原因已经不只是 PTX 有 `spcompress`，而是 CUDA 13.4、TE 2.19、CUTLASS 4.8 和 cuBLAS 13.4 已经开始围绕 SM107/SM107a 建立实际的软件路径。

但另一个判断需要变得更谨慎：**不能再预期 Adaptive Compression 很快会以一个显式的 `TE3 adaptive_compression=True` recipe 暴露给用户。** TE 2.19 已经加入 Rubin SM107a 构建支持，却仍然没有公开 Adaptive Compression API。这更像是在暗示，至少第一阶段它可能是 **TE/cuBLAS/CUTLASS 内部 kernel selection、融合 kernel 或 compiler lowering 的透明优化**，而不是用户手工配置的一种 quantization recipe。([NVIDIA Docs][2])

所以这轮最值得记住的一句话是：

**Rubin Adaptive Compression 的证据已经从“ISA 中能看到它可能怎么做”，推进到了“CUDA 13.4 + TE 2.19 + CUTLASS 4.8 已经开始实际承载 Rubin 对应的数据路径”；但 NVIDIA 仍未公开把 `spcompress / sparse MMA / zero-column mask / LUT-B collector` 中哪几部分正式定义为 TE3 Adaptive Compression。**
