## NVIDIA / Rubin

<a id="nvfp4plus"></a>

### 重点推荐：TensorRT-LLM 接入 NVFP4_PLUS MoE

新路径使用 E2M1 四比特值，每 32 个值配一个 UE5M3 缩放因子，取消 FP32 全局缩放。MXFP4 checkpoint 的数据值保持不变，将原缩放转换为相同二次幂的表示，激活再量化到目标格式，使两次专家矩阵乘均走 FP4。当前限定 Rubin SM107、显式选择的 CuTe DSL 后端及无偏置 SwiGLU 专家，并有维度对齐要求；已合入主分支，尚未给出端到端测量。

[固定提交与源码](https://github.com/NVIDIA/TensorRT-LLM/commit/63468e65433004f8385b1c2975259b950eec633d)

## AMD Instinct

<a id="amd-kimi"></a>

### Kimi K3.1 Pro 官方技术文章：原生 FP4 索引计算

AMD 新文章解释 MI355X 上 ATOM 与 vLLM 的低比特实现。MXFP4 索引键将每项含缩放的存储从 FP8 的 132 字节降到 68 字节，评分使用原生 FP4 矩阵指令，累加与跨头加权归约仍为 FP32；这同时改变存储与计算。文章也介绍专家计算、FP8 激活和上下文并行的配合。测量属于作者给定配置，不能把多项优化合计收益归给量化一项。

[官方技术介绍](https://www.amd.com/en/developer/resources/technical-articles/2026/kimi-k3-1-pro-on-amd-instinct-gpus.html)

<a id="aiter-kv"></a>

### AITER：MXFP4 分页 KV 解码接入共享注意力内核

新增 gfx950、单查询 token 的分页注意力解码路径，读取 E2M1 数据与每 32 元素一个 E8M0 缩放。FP8 查询路径的 QK 使用混合 FP4×FP8 矩阵指令，而 V 会还原为 BF16 后参与 PV；因此不是整个注意力都以 FP4 计算。实现附分页步幅、尾部垃圾值、空上下文等测试。当前是主分支底层能力，模型质量和服务吞吐不能从局部误差测试直接推出。

[固定提交与源码](https://github.com/ROCm/aiter/commit/5469555096de4b7ede0ea6a0cb2d1dd40138fb09)

<a id="aiter-mxfp8"></a>

### AITER：CDNA4 增加 MXFP8 注意力前向与反向

新增面向 gfx950／CDNA4 的 MXFP8 Flash Attention v2 实现，提供前向、反向及携带块缩放的 Python 接口。它扩展低比特训练可用的注意力算子，与上期 gfx1250 路线的新增支持属于不同目标平台。当前依据主分支源码与对应配置核验，不能推断所有 AMD GPU 通用，也没有足够端到端训练数据支持统一速度或收敛结论。

[固定提交与源码](https://github.com/ROCm/aiter/commit/bc12ddf440f9401b2eb9fb2f01930ce05d2d39df)

<a id="mori"></a>

### MoRI：将 all-gather 与消费数据的 FP8 GEMM 融合

新增融合算子把各设备的 token 聚合与后续 FP8 矩阵乘衔接起来，本地块先算，远端数据分块到达后再消费，缩放因子随数据一起传输。all-gather 即让每张卡获得各卡分片的集合通信。作者在八张 MI355X 的指定投影形状上验证通信与计算重叠；这属于融合算子测量，不是整模型加速。当前接口限定节点内通信及所需 SDMA 队列，并需可选 FlyDSL 依赖。

[固定提交与源码](https://github.com/ROCm/mori/commit/e7c16edafedd9f58718b5cce3b7ec398c55bd776)

## AMD Ryzen AI

<a id="ryzen"></a>

### INT4 基座配动态 LoRA：一个 NPU 模型服务多个适配器

官方新博客介绍 Ryzen AI 1.9 的动态 LoRA 流程：以 Quark 将基座量化为 INT4 AWQ，针对冻结基座训练并保留独立适配器，编译后运行时切换。LoRA 是用少量低秩参数适配任务的方法；这里减少为每个任务保留完整合并模型的需要。属于新增机制解读，平台限定 Ryzen AI NPU；文中任务精度结果不能证明所有适配器或模型都可直接通用。

[官方技术介绍](https://www.amd.com/en/developer/resources/technical-articles/2026/dynamic-lora-on-amd-ryzen-ai.html)

## Intel XPU

<a id="intel-grouped"></a>

### PyTorch 接入 oneDNN 分组低比特矩阵乘底层

主分支合入 Intel XPU 分组矩阵乘的 oneDNN 集成部分，面向 FP8、MXFP8、MXFP4 和 NVFP4 等类型。分组矩阵乘可把多个矩阵任务统一提交，是混合专家模型的重要底层能力。此项明确是分阶段接入的第一部分，依赖 oneDNN 版本及后续接口工作，不能写成这些格式已经在全部 XPU 上端到端可用；尚未提供整模型测量。

[固定提交与源码](https://github.com/pytorch/pytorch/commit/77b184a94e545b62e43ea6945f808a86d7518ab4)
